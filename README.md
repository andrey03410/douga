# Douga — генератор аниме-видео

> 動画 (douga) — «видео» по-японски; в аниме-производстве ещё и промежуточные
> фазы анимации.

Веб-приложение — генератор шаблонных видео. Видео бывает трёх видов:

1. **Топ по турниру** — сравнения треков (аудио и/или видео) на сайте строят
   рейтинг, из него собирается видео-«топ».
2. **Свой топ** — позиции и порядок выбирает агент, звук и картинки берутся
   из пула медиа, турнир не нужен.
3. **Пикер** («выбери персонажа / OST / опенинг») — раунды с вопросом,
   карточками или блоками, таймером и ответом.

Рейтинг владелец делает вручную, турниром на сайте. Само видео собирает
AI Video SDK, а автор — внешний агент через MCP. Веб-студия `/studio` показывает
тот же документ: превью, историю, финальный MP4 и публикацию.

Доступ разграничен ролями: гость видит только приветственный экран,
пользователь работает в лимитах, админ может всё; личный кабинет управляет
файлами на сервере.

**AI Video SDK** хранит проекты топа и пикера как канонический JSON,
с редактированием через внешний MCP-клиент, историей и устойчивой очередью.
Для SDK доступны 16:9, 9:16 и 1:1. Число карточек и раундов ограничивают
технические бюджеты схемы.
См. [работу с SDK](#ai-video-sdk).

Для разработки (и для ИИ-агентов) вход — [`AGENTS.md`](AGENTS.md): карта зон
кода в [`.ai/map/`](.ai/map/), стадии задач в [`.ai/features/`](.ai/features/),
история фаз — [`.ai/history.md`](.ai/history.md).

## Стек

- **Next.js 14** (App Router, React 18) — фронт + API.
- **Prisma 7 + SQLite** через адаптер `better-sqlite3` (для Postgres понадобятся другой `provider` и другой адаптер).
- **Auth.js (next-auth v5)** — email + пароль.
- **Remotion** — общий Player и рендер SDK (1920×1080, 1080×1920, 1080×1080; H.264/AAC).
- **ffmpeg-static** — декод/нарезка аудио, RMS-анализ активного сниппета.
- **Vitest** — тесты.

## Требования

Перед запуском должны быть установлены:

| Что                         | Зачем                                   | Как проверить            |
|-----------------------------|------------------------------------------|--------------------------|
| **Node.js 22** (проверено на 22.23.2) | Next.js 14, бэкенд; `mcp` и `studio:worker` требуют `--env-file-if-exists` | `node -v`                |
| **npm** (идёт с Node)       | установка зависимостей                   | `npm -v`                 |
| **Google Chrome / Chromium** | только для **рендера MP4** (Remotion)   | `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --version` |

Ставить отдельно **не нужно**: ffmpeg (идёт в комплекте — пакет
`ffmpeg-static`), SQLite (пакет `better-sqlite3`), Remotion/React/Prisma и прочее —
всё приходит через `npm install`.

## Быстрый старт

```bash
npm install
cp .env.example .env          # отредактируйте AUTH_SECRET и ADMIN_EMAILS
npm run db:push               # создаёт SQLite-схему (prisma/dev.db) и Prisma-клиент
npm run dev                   # http://localhost:3000
```

`ADMIN_EMAILS` — email-ы (через запятую), которые автоматически получают роль
администратора при входе/регистрации.

### Браузер для рендера (важно)

Рендер MP4 выполняется Remotion-ом в headless-браузере. Какой браузер
использовать, задаёт переменная **`REMOTION_BROWSER_EXECUTABLE`** в `.env`:

- Укажите путь к установленному Chrome/Chromium — например,
  `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` (macOS),
  `/usr/bin/google-chrome` (Linux).
- Если переменная **не задана**, Remotion попытается **скачать из интернета**
  свой chrome-headless-shell; в окружении без сети рендер упадёт с ошибкой
  вида «could not download / no browser executable». Скачивание можно сделать
  заранее: `npx remotion browser ensure`.
- Всё остальное (сравнения, студия, живое превью) работает **без**
  браузера — он нужен только воркеру студии (`npm run studio:worker`) для
  кадров, клипов и финального MP4.

## Роли

| Роль    | Возможности                                                                 |
|---------|------------------------------------------------------------------------------|
| Гость   | Только приветственный экран (описание возможностей + вход/регистрация)       |
| Пользователь | Турниры, пул и студия с живым превью; лимиты: 1 архив ≤100 МБ, пул медиа ≤100 МБ; финальный MP4 недоступен |
| Админ   | Всё без лимитов (архив до 10 ГБ) + админка: роли и удаление пользователей     |

Роль читается из БД на каждый запрос — смена роли действует сразу, без
перелогина. Проверки в коде идут по пермишенам через матрицу
`src/lib/domain/permissions.ts`; новая роль добавляется одной записью в неё.
**Личный кабинет** (`/account`): профиль, квоты «занято X из Y», архивы и пул
медиа с размерами, импорт в пул (файлы, ссылка, Shikimori, `Ctrl+V`), сводка
студии и публикации — удаление стирает файлы с сервера.

## Поток использования

1. Регистрация / вход.
2. **Создать топ**: название, схема (сравнительная сортировка / швейцарка / круговая),
   **сколько сравнивать за раз** (2–7), слепой режим (опц.), ZIP-архив с треками —
   аудио (mp3/m4a/flac/…) и/или видео (mp4/webm/mov, рекомендуется MP4 H.264+AAC),
   лимит 10 ГБ (админ) / 100 МБ (пользователь). Инструкция «Как подготовить архив»
   — прямо на форме.
3. **Сравнения**: прослушать/просмотреть варианты и ответить. Пара — как раньше:
   лево / ничья / право. Группа из 3–7 — **клики по порядку**: первый клик даёт
   первое место, последний оставшийся встаёт сам, цифровые клавиши работают как
   клики. Не хочется различать хвост — «остальные примерно равны». Видео-треки
   играют в видеоплеере; в слепом режиме скрываются и названия, и видеоряд (трек
   играет как аудио до «Показать названия»). Прогресс сохраняется.
4. **Итоговый топ**: выбрать размер top-N и при желании переставить позиции ↑↓.
5. **Видео**: попросить агента «сделай видео по турниру …» — он найдёт турнир
   через MCP по названию — или нажать «Создать видео через SDK →» и получить
   SDK-проект. Оформление, клип и финальный MP4 — в студии `/studio/<id>`.

**Множественные сравнения (сколько за раз)** — отдельная настройка, а не ещё
одна схема: схема решает, кого с кем спрашивать, а размер группы — сколько
треков попадёт на один экран. Смысл в прослушиваниях, а не в кликах: одно
прослушивание в группе обслуживает несколько сравнений, поэтому ранжирование
тройки даёт 1,7× информации на прослушивание, пятёрки — 2,8×. Важная деталь:
платит именно **полное ранжирование** группы, а не «выбери лучшего из четырёх» —
второе по информации на прослушивание не лучше пары.

- Швейцарка и круговая работают с группами; **сравнительная сортировка — только
  парами** и честно об этом пишет: она и так работает на информационном пределе,
  и группы ей ничего не дают.
- Размер можно менять **прямо посреди турнира** — в базе всё равно лежат пары.
- План — «каждый трек получает `ceil(log₂ N)` соперников», формула не зависит от
  размера группы и при 2 сворачивается в нынешние `ceil(log₂ N)` раундов. На 201
  треке: пары — 800 экранов, тройки — 268, пятёрки — 82.
- План не тюрьма: рядом с прогрессом видно, **на сколько процентов пар порядок
  уже определён** (транзитивное замыкание лога), и когда план пройден, можно
  либо смотреть топ, либо взять **ещё раунд**. На реальных данных: тот же
  бюджет прослушиваний, что и сегодня, поднимает определённость с 36 % до 99 %.
- Индикатор честный: он же показывает **противоречия**. Живые предпочтения
  нетранзитивны (в реальном турнире 28 % треков оказались в циклах), и такие
  пары не «дорешиваются» в порядок, а показываются как противоречия.
- «Отменить последний ответ» убирает **экран целиком**, а не одну его пару.

**Источники в менеджере медиа** собраны в один ряд табов — «Файлы · Ссылка ·
Shikimori» — так сетка пула начинается сразу под активным источником, а не под
тремя развёрнутыми панелями. На любом табе работает **вставка из буфера**
(`Ctrl+V`): скриншот или скопированный файл загружается как обычный файл и
получает имя «Вставка ДД.ММ ЧЧ:ММ» (если буфер отдал безымянный `image.png`), а
картинка, скопированная в браузере, приезжает ссылкой и уходит в импорт по
ссылке. Вставка в текстовое поле остаётся обычной вставкой текста.

**Картинки по ссылке**: поле ссылки одно на все виды медиа. Если адрес ведёт на
картинку (`jpg`/`png`/`webp`/`gif`), она скачивается **сразу** (`POST
/api/arts/from-url`) и появляется в пуле — без фоновой джобы. Ограничения:
только `http(s)`, `Content-Type` должен быть картинкой, 32 МБ, таймаут 15 с, не
больше 3 редиректов, и ни один хоп не может вести в приватный диапазон адресов
(защита от SSRF; для домашней установки с медиа на NAS это снимается
`MEDIA_URL_ALLOW_PRIVATE=1` в `.env`). Если по ссылке оказалась не картинка,
рядом появляется кнопка «Скачать как видео/аудио» — тот же адрес уходит в
yt-dlp, перенабирать не нужно.

**Импорт видео и аудио по ссылке**: в менеджере медиа можно вставить ссылку на видеоролик
(YouTube и другие сайты, поддерживаемые yt-dlp) — сервер скачает его **фоново**
в пул: режимы «Видео до 480/720/1080p» (H.264+AAC mp4) и «Только звук» (m4a).
Прогресс и отмена — в том же окне; окно можно закрыть, файл появится в пуле.
Квота пула действует: оценка размера до старта + жёсткий кап во время
скачивания. Бинарник yt-dlp приложение само скачивает с официального GitHub
в `storage/bin` при первом использовании (переопределяется `YTDLP_PATH` в
`.env`) и самообновляется, когда YouTube ломает старые версии.

> **Если ссылка распознаётся (название видно), а загрузка падает с ошибкой
> про видео-CDN** — сеть сервера блокирует `googlevideo.com` (типичная
> ситуация: youtube.com открывается, CDN — нет). Решение: задать прокси/VPN
> в `YTDLP_PROXY` в `.env` (http:// или socks5://) и перезапустить сервер.

**Уборка пула**. У карточки видно, чем занят файл: «не используется» или
«N ссылок в проектах Studio». Медиа, на которое ссылается студия, удалить
нельзя. Чекбокс в углу карточки включает выделение, `Shift`-клик
берёт диапазон, «Удалить выбранные» сносит до 200 файлов за раз и честно
сообщает, что не получилось. Имя правится на месте: карандаш подсказывает, что
поле редактируемое, `Enter` сохраняет с отметкой «✓ сохранено», `Esc` отменяет,
а отказ сервера показывается текстом и откатывает поле.

**Личный кабинет** (`/account`) показывает сводки, а списки грузит по запросу:
«Пул медиа: 1332 файла · 213 МБ · картинки 1312 · видео 0 · аудио 20» и кнопка
«Показать все» — дальше тот же список, что в менеджере (поиск, фильтр по типу,
миниатюры, переименование, выделение и удаление), страницами по 40. Так же
устроены «Архивы». Импорт в пул (файлы, ссылка, Shikimori, `Ctrl+V`) тоже
здесь и виден, даже если список свёрнут. Сводка считается агрегатами, поэтому
страница не тянет тысячу строк. Раздела со старыми MP4 в кабинете нет:
готовый ролик скачивают в `/studio/<id>`.

**Поиск в Shikimori**: рядом с импортом по ссылке в менеджере медиа есть блок
поиска Shikimori — переключатель «Аниме / Персонажи», поле с дебаунсом ~300 мс
и живой дропдаун (мини-постер + факты: год · тип · рейтинг для аниме, имя
ru/en для персонажа). Клик «⬇ В пул» **синхронно** качает постер и добавляет
его в пул как обычную картинку (`Art`, с учётом квоты и роли). Базовый хост
задаётся `SHIKIMORI_BASE_URL` в `.env` (домен API периодически мигрирует —
смена одной переменной переносит интеграцию на новый хост); `SHIKIMORI_USER_AGENT`
задаёт заголовок User-Agent для запросов к API.

Скачивается **тот постер, который показан на сайте**, в полном разрешении:
старый REST-путь `/system/animes/original/<id>.jpg` отдаёт уменьшенную и иногда
устаревшую копию (например «Атака титанов»: 225×350 против 685×975 на сайте), а
актуальный файл берётся из GraphQL-поля `poster.originalUrl`
(`/uploads/poster/...`). Если свежий URL недоступен, импорт молча откатывается на
старый путь. Запросы к Shikimori соблюдают оба лимита сервиса (5 в секунду и 90 в
минуту): они выстраиваются в очередь со скользящим окном, а 429 повторяется с
паузой (с приоритетом заголовка `Retry-After`) — большие агентские сценарии на
сотни запросов больше не отваливаются по лимиту.

**Мои видео** (`/projects`) — список SDK-проектов и подсказка, как подключить
MCP. Видео собирает агент: топ по готовому турниру, свой топ из пула или пикер.
С сайта рейтинг по-прежнему делают турниром. На странице результатов кнопка
«Создать видео через SDK» открывает проект, который можно отдать агенту.

**Групповое сравнение турнира**: на экране можно ранжировать не пару, а группу
до 7 треков. Это сравнение вкуса. Визуал ролика по этому рейтингу собирает агент.

## AI Video SDK

JSON `VideoDocument` — основной формат проекта. TypeScript builders из
`src/video` создают тот же JSON. Документ объединяет источник участников,
привязки к своему пулу, сцены, оформление и звук. Топ допускает объекты без
аудио; пикер поддерживает группы, memory, портретные карточки, дугу, свободное
размещение и отдельный ответ. Новые эффекты добавляет разработчик в схему,
компилятор и общий рендерер; произвольный JS/TSX из документа сервер не исполняет.

Короткий маршрут для агента: `video_preset_list({recipes:true,kind,format})` →
`video_preset_get` с формой/примером → создание проекта → `video_content_set`
с собственными материалами → `video_storyboard` → `video_review`.
Галерея `/studio/recipes` показывает 33 визуальных рецепта и позволяет примерить
до трёх вариантов на своём проекте. `/studio/<id>/storyboard` показывает сетку,
страницы, замечания, выбранные исправления, восстановление и сравнение до/после
с опциональным pixel diff/PSNR. Просмотр не создаёт ревизию и не публикует видео.
Детальный [маршрут SDK](.ai/features/32-storyboard-reference/sdk-guide.md).

1. Войдите в свой аккаунт и откройте `/projects` → создание SDK-проекта
   (`/studio/new`). Можно начать с «Пример топа» или «Пример пикера», вставить
   полный JSON и нажать «Создать SDK-проект». В результатах турнира SDK-кнопка
   сначала сохраняет выбранный top-N и затем подключает источник рейтинга.
2. На `/studio/<id>` нажмите «Открыть SDK». «Сохранить и проверить» сохраняет
   черновик, включая ошибочный JSON; «Зафиксировать ревизию» создаёт версию
   истории после успешной проверки. Изменения источника обновляют участников
   по стабильным ID, сохраняя их оформление и медиа.
3. «Показать превью» явно открывает Player без автозапуска. Ошибочный черновик
   оставляет последнее корректное превью с отметкой его происхождения.
   «Открыть медиа» позволяет отдельно посмотреть картинку, послушать звук или
   открыть видео. Ответы и медиа могут раскрывать содержание проекта.
4. В «История и различия» можно сравнить версии и восстановить старую как
   новую ревизию. При параллельной правке локальный текст сохраняется с
   исходным номером версии; сначала сравните его с сервером. Явная команда
   «Загрузить серверную версию» заменяет буфер редактора.
5. «Каталог пресетов» содержит 87 встроенных вариантов (54 пресета и 33 рецепта)
   и личные пресеты. Рецепты по умолчанию сохраняют авторские сцены, длительности
   и локальные настройки; явный режим replace заменяет только оформление.
   «Сохранить оформление из SDK» убирает конкретные медиа, участников, вопросы
   и ответы. «Применить пресет» меняет оформление черновика, сохраняя содержание;
   «Новый проект с пресетом» создаёт независимый проект с абстрактными слотами.
6. Создайте PNG, короткий MP4, аудиофрагмент или финальный MP4 в панели заданий.
   Задание фиксирует ревизию, медиа и движок. Последующая правка или изменение
   рейтинга не меняют старый результат и не запускают новый рендер.
   Готовый результат открывается явно и доступен через «Скачать результат».

В разработке нужны два терминала в папке проекта:

```bash
# Терминал 1: сайт
npm run dev

# Терминал 2: исполнитель устойчивой очереди SDK
npm run studio:worker
```

Используйте Node.js с поддержкой `--env-file-if-exists`; SDK проверен на
Node.js 22.23.2. `.env` загружается процессами, но явно переданные переменные
окружения имеют приоритет. Отдельный MCP-клиент запускает `npm run mcp` с
`MCP_ACTOR_EMAIL` уже зарегистрированного владельца. Email должен совпадать с
веб-аккаунтом, в котором вы хотите видеть проекты; пароль MCP не нужен.
Права, владение ассетами и квоты проверяются повторно при выполнении задания;
финальный рендер доступен администратору. Веб-запрос только ставит задание в
очередь. Список проектов — на `/projects`.

Основные MCP-вызовы (аргументы ниже — примеры для внешнего клиента):

```js
video_capabilities({})
video_schema_get({ name: "document" })
video_schema_get({ name: "services" })
video_examples({})
video_preset_list({ limit: 100 })
video_project_create({ presetId: "picker.classic.square", roundCount: 1,
  cardsPerRound: 4, idempotencyKey: "my-create-unique-key" })
video_project_get({ projectId: "PROJECT_ID" })
video_document_get({ projectId: "PROJECT_ID", section: "head" })
video_project_validate({ projectId: "PROJECT_ID" })
video_timeline_get({ projectId: "PROJECT_ID", revision: 1, limit: 100 })
video_job_start({ projectId: "PROJECT_ID", kind: "clip", revision: 1,
  expectedVersion: 1, fromFrame: 0, durationFrames: 90,
  idempotencyKey: "my-job-unique-key" })
video_job_get({ jobId: "JOB_ID" })
```

Заменяйте номера версии/ревизии фактическими значениями и не задавайте диапазон
длиннее таймлайна. `expectedVersion` защищает от конкурентной правки;
`revision` выбирает сохранённый документ. При повторе одного запроса используйте
тот же `idempotencyKey`; ключи общие для аккаунта, другой запрос требует новый
ключ. Для правки доступны `video_draft_replace`, `video_draft_patch`,
`video_draft_commit`, для истории — `video_history_list`, `video_revision_restore`.
`video_import_start` ставит импорт по ссылке в ту же устойчивую очередь.
`video_job_cancel` отменяет своё задание; `video_job_inspect` и
`resources/read` с `video://job/JOB_ID` явно запрашивают результат.
Эти URI работают в аутентифицированном MCP-соединении; отображение и
воспроизведение зависят от внешнего клиента. MCP читает не более 12 MiB за
один медиарезультат. Больший файл скачивается на сайте через текущую сессию
(`/api/studio/jobs/JOB_ID/result?download=1`).

Точные схемы, бюджеты и поведение опубликованы в контрактах
[SDK](.ai/specs/22-ai-video-sdk-contract.md),
[сервиса](.ai/specs/23-ai-video-service-contract.md),
[очереди и ресурсных ограничений](.ai/specs/24-ai-video-job-contract.md),
[сайта и HTTP](.ai/specs/25-ai-video-http-contract.md).

### Повторяемая проверка SDK

Используйте отдельный проверочный аккаунт и его медиа. Во время проверки
остановите общий `studio:worker`: драйвер сам запускает только
`--once --job ID` для созданного им задания. Не запускайте его одновременно с
автотестами, использующими ту же SQLite и тяжёлый слот.

```bash
# Существующая сохранённая ревизия; черновик не фиксируется
node scripts/verify-studio.mjs --actor you@example.com \
  --project PROJECT_ID --kind clip --seconds 3 \
  --output storage/studio-verification/my-clip

# Новый отдельный проект из полного JSON; финальный MP4 требует admin
node scripts/verify-studio.mjs --actor you@example.com \
  --document /absolute/path/to/video.json --kind render \
  --output storage/studio-verification/my-render
```

`--actor` обязателен даже при наличии `MCP_ACTOR_EMAIL` в `.env`; скрипт не
читает пароли и не меняет `.env`. `--kind` — `still|clip|audio|render`, по
умолчанию `clip`; фрагменты начинаются с кадра 0, `--seconds` по умолчанию 3,
максимум 15. `render` использует всю ревизию. `--timeout` ограничивает весь
прогон (по умолчанию 600 секунд). Каталог результата должен быть новым.

Драйвер проверяет настоящий stdio MCP, схемы, каталог встроенных пресетов,
валидацию и сохранённый таймлайн, ставит задание с номером ревизии и запускает
его отдельным CLI. Для результата в пределах MCP-бюджета он читает реальные
байты, сверяет SHA-256, размер и MIME type, сохраняет `artifact.*` и
`summary.json` с размерами/FPS/длительностью из задания. Код выхода 0 означает
успешную проверку байтов; 1 — ошибку, отмену или таймаут; 2 — рендер завершён,
но нужен отдельный аутентифицированный download из-за бюджета MCP (байты ещё
не проверены). Остальные JSON и `process.log` сохраняют доказательства и
диагностику; содержимое может включать ответы, поэтому храните каталог приватно.
Чтение связанного проекта выполняет обычную синхронизацию источника, но драйвер
не заменяет и не фиксирует его черновик. Визуальную читаемость, звук и живой
Player проверяют отдельно; текущие результаты записаны в
[журнале приёмки](.ai/phases/phase-20-verification.md).

## MCP-сервер (ИИ собирает видео)

Приложение работает как **MCP-сервер** (stdio). Внешний ИИ ищет материал в
Shikimori, кладёт медиа в пул и собирает ролик инструментами `video_*`.
При подключении сервер отдаёт инструкцию с тремя путями: топ по турниру,
свой топ из пула и пикер. Финальный MP4 (`video_job_start` с `kind:"render"`)
требует роль администратора. Нужен запущенный `npm run studio:worker`.

### Запуск

MCP-сервер действует от имени одного аккаунта. Укажите его email и запустите:

```bash
# .env
MCP_ACTOR_EMAIL="you@example.com"   # email уже зарегистрированного аккаунта
# DOUGA_PUBLIC_URL="http://localhost:3000"  # база ссылки /watch/… из video_publish
# необязательно: папки, из которых ИИ может забирать медиа с диска (через ':')
MCP_LOCAL_MEDIA_DIRS="~/Музыка/ost:~/Картинки/фоны"
# необязательно: разрешить импорт картинок по ссылке с адресов локальной сети
# (по умолчанию приватные адреса запрещены — защита от SSRF)
MEDIA_URL_ALLOW_PRIVATE=1

npm run mcp
```

Без `MCP_LOCAL_MEDIA_DIRS` инструменты `list_local_media`/`import_local_media`
отвечают `LOCAL_MEDIA_DISABLED`: доступа к диску по умолчанию нет. Путь вне
разрешённых папок (в том числе через `..` или симлинк) — `PATH_NOT_ALLOWED`.
Оригиналы файлов не перемещаются: в пул уходит копия.

Права и квоты берутся из роли этого аккаунта (импорт требует роль с
`media:upload`; размер пула ограничен квотой роли).

### Доступные инструменты

46 имён: 11 `shikimori_*`, 5 инструментов пула и 30 `video_*`. Полный набор
отдаёт `tools/list`. Семейство SDK описано в [разделе AI Video SDK](#ai-video-sdk).
`artId` из пула в документе — это `assetId` привязки `{kind:"pool"}`.

| Инструмент | Назначение | Возвращает |
|---|---|---|
| `shikimori_find_studio` | найти студию по названию | `[{id, name}]` |
| `shikimori_studio_animes` | аниме студии (по популярности) | `[{id, type, label, posterPath, facts}]` |
| `shikimori_anime_characters` | персонажи аниме (по умолчанию Main) | `[{id, type, label, posterPath}]` |
| `shikimori_search` | поиск аниме/персонажа по названию | `[{id, type, label, posterPath, facts}]` |
| `shikimori_character` | персонаж и все его аниме (старые первыми); `debutYear` — год первого появления, то есть «эпоха» самого персонажа | `{id, label, posterPath, debutYear, animes:[{id, label, kind, year}]}` |
| `shikimori_anime` | аниме с производственными студиями (спонсоры отброшены), годом, оценкой и жанрами — основа раундов «студия против студии» | `{id, label, kind, year, score, posterPath, studios:[{id, name}], genres, facts}` |
| `shikimori_find_user` | пользователь по нику (или числовому id) | `{id, nickname, url, avatarUrl}` |
| `shikimori_user_anime_list` | список аниме пользователя с **его** оценками и статусами; фильтры `status` (`planned`/`watching`/`rewatching`/`completed`/`on_hold`/`dropped`/`all`), `minScore`, порядок `score`/`updated`/`name`, `limit` ≤ 500 | `{user, total, countsByStatus, matched, items:[{id, label, kind, posterPath, userScore, status, episodes, rewatches, updatedAt}]}` |
| `shikimori_user_favourites` | избранное пользователя: аниме и персонажи (пути постеров готовы к импорту) | `{user, animes, characters}` |
| `list_pool` | что уже лежит в пуле (фильтры `kind`/`query`, `filePath` абсолютный) | `{arts:[{id, label, kind, durationSec, hasAudio, sizeBytes, filePath, createdAt}], nextCursor}` |
| `list_local_media` | медиа-файлы папки на диске (только из `MCP_LOCAL_MEDIA_DIRS`) | `{dir, roots, files:[{name, path, kind, sizeBytes}]}` |
| `import_local_media` | импорт локальных файлов в пул (оригиналы остаются на месте, ≤ 50 за вызов) | `{items:[{artId, label, kind, durationSec, sizeBytes}], failed:[{path, error}]}` |
| `import_shikimori_poster` | импорт постера в пул как картинку | `{artId}` |
| `import_youtube_audio` | скачать звук с YouTube (yt-dlp) в пул | `{artId}` |

### Три пути к ролику

- **Топ по турниру.** `video_source_list` ищет турнир по названию, `video_project_create` с `presetId` топа (например `top.classic.wide`) и `sourceId` турнира берёт его рейтинг, дальше оформление, `video_project_validate`, `video_draft_commit` и `video_job_start`.
- **Свой топ.** Звук и картинки кладутся в пул. Документ с `source.kind:"manual"`, у участников есть `rank` и привязки `{kind:"pool", assetId}`. Фрагмент `settings.top.snippet` в режиме `active` сам находит громкое место. Пример — `top-manual` в `video_examples`.
- **Пикер.** Пресеты `picker.*` и пример `picker-groups` в `video_examples`. Постеры ищутся через `shikimori_*` и импортируются в пул.

Правки документа передают `expectedVersion`. Повтор того же шага — с тем же `idempotencyKey`.

## Тесты

```bash
npm test
```

Покрытие (830 тестов):
- доменные движки турнира (merge / swiss / round-robin): завершаемость,
  возобновляемость, корректность ранжирования, тай-брейки, граничные случаи;
- множественные сравнения (фаза 18): разбор ответа группы в пары (полное
  ранжирование, ранний стоп, пара), целевое число соперников и оценка экранов;
  определённость порядка через транзитивное замыкание (цепочка, цикл, ничья не
  задаёт порядок, поле в 300 треков); движки с группами 2–5 — завершаемость, ни
  одной повторной пары, ноль противоречий на согласованных ответах, прогресс не
  выходит за 100 %, устойчивость к смене размера посреди раунда, к «всё примерно
  равно» на каждом экране и к покупке лишних раундов до исчерпания пар;
  merge держится пар при любом запросе;
- интеграционные тесты групповых сравнений на реальной БД: пачка на экран,
  ничьи для нерасставленного хвоста, отказ от устаревшего экрана, отмена экрана
  целиком (и повторный показ отменённого), кламп размера по полю и по схеме,
  «ещё раунд» поднимает определённость и упирается в исчерпание пар, номер
  экрана не обгоняет оценку, противоречия показываются, а не заметаются,
  завершённый турнир не открывается заново и остаётся доступен для смены top-N;
- RMS-выбор активного сниппета;
- разбор имён/тегов при загрузке, определение типа файла (аудио/видео);
- интеграционный тест полного потока турнира на реальной БД (Prisma + движок +
  ранжирование);
- интеграционные тесты пула медиа на реальной БД (поиск/пагинация/фильтр
  по типу, загрузка видео с пробой длительности/звука и постером, переименование,
  отказ удалять медиа со ссылками студии, изоляция чужих данных);
- роли и пермишены: матрица прав/квот, лимит архивов (включая гонку двух
  параллельных загрузок), квота пула, бутстрап админа по `ADMIN_EMAILS`,
  сводка кабинета с бэкфиллом размеров, админ-операции (смена роли,
  удаление пользователя с файлами, защита от self-demote/self-delete);
- библиотека медиа (фаза 17): классификация ссылок (картинка / для yt-dlp /
  не ссылка), `Content-Type` → расширение, политика адресов (localhost,
  `*.local`, приватные и служебные диапазоны IPv4/IPv6, IPv4-mapped), метка из
  URL; чтение буфера (HTML `<img src>` важнее текста, текстовая ссылка только
  если это картинка, метка вставки, безымянные файлы); формулировки
  использований студии и их сумма по выделению, русские множественные формы; импорт
  картинки по ссылке против локального HTTP-сервера (успех, не-картинка,
  превышение лимита по заголовку и по факту байт, редирект на loopback, дохлая
  ссылка, квота — без осиротевших файлов в `storage/tmp`); массовое
  удаление (частичные отказы, дубликаты, пустая и переполненная пачка);
  кабинет на агрегатах (разбивка пула по типам, бэкфилл размеров треков,
  изоляция чужих данных);
- импорт по ссылке: yt-dlp-аргументы/селекторы/парсер прогресса/классификатор
  ошибок (юнит) и полный конвейер на локальном HTTP-источнике (видео и аудио
  в пул с пробой/постером, мёртвая ссылка, блокировка по квоте, лимит
  2 параллельных, отмена, изоляция);
- импорт из Shikimori: маппинг аниме/персонажа, фолбэк подписи (русское имя →
  оригинал), валидатор пути постера от SSRF (чужой хост, не-`/system`,
  traversal, абсолютный URL) — юнит; и интеграционный конвейер на реальной БД
  с локальным HTTP-источником вместо Shikimori (поиск нормализуется,
  синхронный импорт постера создаёт `Art(image)` с учётом квоты, отказ по
  квоте, отказ импорта при невалидном пути);
- список и избранное пользователя Shikimori: маппинг профиля и записи списка
  (оценка 0 → «нет оценки», манга и неизвестные статусы отбрасываются), фильтры
  по статусу/оценке, три порядка, счётчики по статусам, избранное (миниатюра
  `x64` → путь постера, мусор пропущен), плейсхолдер «нет арта» → null — юнит;
  интеграционно на локальном стенде: ник и id, `USER_NOT_FOUND`, «список одним
  запросом», импорт постера избранного персонажа в пул, ретрай при 429 и явная
  ошибка после исчерпания попыток;
- лимиты и свежие постеры Shikimori: политика ожиданий (пауза, скользящее окно,
  устаревшие метки, расписание повторов и `Retry-After`) — юнит; гард на URL
  постера (чужой хост, другой протокол/порт, не-poster путь, traversal);
  интеграционно — импорт берёт свежие байты вместо legacy-копии, готовый
  `posterUrl` не тратит лишний GraphQL-запрос, три сценария фолбэка (нет
  постера / GraphQL 500 / чужой хост) дают legacy-копию.

Кроме того, вручную провалидированы (см. историю разработки):
- ролевой E2E: гость/пользователь/админ, лимиты 403/413, смена роли без
  перелогина, кабинет и админка;
- импорт в пул по ссылке и из Shikimori, в том числе с сайта в кабинете;
- студийный рендер: клип и финальный MP4, кадры и декодированный звук;
- MCP: 46 инструментов, инструкция сервера, топ по турниру, свой топ и пикер.
