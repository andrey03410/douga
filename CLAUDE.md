# tournament-bracket-video

Проект для построения турнирных сеток по различным правилам и последующего рендера
шаблонного видео в формате «топа».

## Где лежит ИИ-информация

> **Вся ИИ-информация проекта (спецификации, фазы разработки, исследования, заметки,
> контекст для агента) хранится в директории [`.ai/`](.ai/).**
> Это единый источник истины. Перед началом любой задачи сверяйся с содержимым `.ai/`.

Структура `.ai/`:

| Папка            | Назначение                                                              |
|------------------|-------------------------------------------------------------------------|
| `.ai/specs/`     | Спецификации проекта — что и как должно работать                        |
| `.ai/phases/`    | Разбивка спецификации на фазы разработки (план + статус выполнения)      |
| `.ai/research/`  | Исследования, заметки, сравнение подходов и библиотек                    |

При появлении новых типов ИИ-материалов добавляй соответствующие подпапки в `.ai/`.

## Структура проекта

```
tournament-bracket-video/
├── .ai/                 # вся ИИ-информация (см. выше)
├── src/                 # исходный код
├── assets/
│   ├── templates/       # шаблоны видео / сеток
│   └── media/           # медиа-ресурсы (изображения, шрифты, аудио)
├── output/              # результаты рендера
└── CLAUDE.md
```

`shikimori_find_user` (ник или id), `shikimori_user_anime_list` (его оценки и

статусу и минимальной оценке, порядок score/updated/name, сводка

списку), `shikimori_user_favourites` (аниме и персонажи; `x64`-миниатюра
переписывается в путь постера); записи без арта отдают `posterPath: null`,
запросы к Shikimori сериализуются с паузой и повторяются при 429, Фаза 14 —
надёжность Shikimori: клиент держит оба лимита сервиса (5/сек и 90/мин, чистая
политика в `lib/domain/rate-limit.ts` — скользящее окно + расписание повторов с
`Retry-After`), а импорт постера берёт файл как на сайте (GraphQL
`poster.originalUrl`, `/uploads/poster/...`, полное разрешение) с откатом на
старую `/system`-копию, Фаза 15 — оформление проекта из MCP: чтение пула
(`list_pool`, отдаёт и абсолютный путь файла), задний фон и настройки проекта
(`set_project`, `backgroundArtId`), импорт медиа прямо с диска
(`list_local_media`/`import_local_media` в границах allowlist
`MCP_LOCAL_MEDIA_DIRS`, оригиналы не перемещаются — в пул уходит копия),
`get_project` показывает фон, `playlistSec` и плановый `durationSec`, чтобы
плейлист подбирался под хронометраж, Фаза 16 — групповое сравнение: у раунда
режим `single`/`groups`, в групповом 2–3 блока по 1–5 карточек (всего ≤ 15),
плашка с названием и знак VS в кадре, один размер карточки на раунд
(`groupLayout` в `lib/domain/picker-layout.ts` перебирает разбиения блоков),
шаг таймлайна — блок с каскадом карточек, ответ отмечается на блоке
(необязателен), в блоке звучит первая карточка с видео+звуком; конструктор
переключает режим и переносит карточки между блоками, MCP получил
`add_group`/`set_group`/`delete_group` и `groupId` в `add_tile*`; плюс
`shikimori_character` — аниме персонажа и `debutYear` (год первого появления:
эпоха персонажа считается по дебюту, а не по сезону, из которого взят постер) и
`shikimori_anime` — студии/год/оценка аниме (для раундов «студия против
студии»); подпись карточки в кадре масштабируется под её размер и переносится
на 2–3 строки, Фаза 17 — библиотека медиа: картинки приходят из сети
(`POST /api/arts/from-url` — синхронное скачивание с лимитами 32 МБ/15 с/3
редиректа и запретом приватных адресов, снимается `MEDIA_URL_ALLOW_PRIVATE`) и
из буфера обмена (`Ctrl+V` в модалке: файл → HTML `<img src>` → текстовая
ссылка), источники убраны в табы «Файлы · Ссылка · Shikimori», одно поле ссылки
делит адреса через `classifyMediaUrl` и предлагает yt-dlp, когда по ссылке не
картинка; переименование инлайн с «✓ сохранено», `Esc` и откатом при ошибке;
счётчик использований считает все восемь связей `Art` (позиции топов, карточки
раундов, плейлист, фоны), а подтверждение удаления называет последствия —
карточки раундов и треки плейлиста уходят каскадом; мультивыбор `Shift`-кликом
и массовое удаление до 200 файлов; личный кабинет отдаёт агрегаты и грузит
списки по запросу (пул — тем же `useMediaPool`/`MediaBrowser`, что менеджер;
`RenderJob.outputBytes` вместо `stat` на каждый MP4), Фаза 18 — множественные
сравнения: «сколько сравнивать за раз» (`Tournament.groupSize`, 2–7) — отдельная
ось, а не новая схема; экран ранжируется кликами по порядку (последний
оставшийся встаёт сам, цифровые клавиши, «остальные примерно равны» пишет
нерасставленный хвост ничьими), при 2 остаётся сегодняшняя раскладка
«лево/ничья/право»; группы едят швейцарка и круговая, merge объявляет
`maxGroupSize = 2` (он и так на информационном пределе); движки получили
`nextQuestion(items, log, groupSize, bonusOpponents)`, `nextPair` — обёртка при
2; швейцарка больше не симулирует расписание, а строит следующую группу от
состояния лога (иначе смена размера посреди раунда восстанавливала бы
несуществовавшее расписание); план — `ceil(log₂ N)` соперников на трек (не
зависит от размера группы, при 2 = нынешние раунды), сверху «Ещё раунд» через
`bonusOpponents`; экран = `ComparisonBatch` (отмена целиком, прогресс в экранах,
возобновление при менявшемся k), чтения батчей и сравнений добивают сортировку
по `id` — SQLite штампует миллисекунды; определённость порядка считается
транзитивным замыканием (`order-coverage.ts`) и честно показывает противоречия:
живые предпочтения нетранзитивны, в реальном турнире 28 % треков в циклах,
поэтому транзитивный вывод не делаем.
Стек: Next.js + Prisma (SQLite) + Auth.js + Remotion + ffmpeg-static +
react-easy-crop. Запуск и инструкции — в [`README.md`](README.md).

## AI Video SDK — фаза 20

Канонический JSON и TypeScript builders находятся в `src/video`; единый
компилятор/StudioVideo используется Player, PNG, короткими клипами и итоговым
MP4. Документ не исполняет произвольный JS/TSX. Для новых эффектов расширяйте
версионированные схемы, компилятор и рендерер. Прежние конструкторы остаются
отдельно; ограничения 9 карточек/50 раундов не переносите в SDK.

Сверяйтесь с фактическими контрактами:
[22 SDK](.ai/specs/22-ai-video-sdk-contract.md),
[23 сервис](.ai/specs/23-ai-video-service-contract.md),
[24 очередь и технические бюджеты](.ai/specs/24-ai-video-job-contract.md),
[25 сайт/HTTP](.ai/specs/25-ai-video-http-contract.md).
Доверенный актор MCP задаётся `MCP_ACTOR_EMAIL` зарегистрированного аккаунта;
его email должен совпадать с веб-аккаунтом. Сервисы повторно проверяют права,
владение и квоты. Финальный рендер остаётся admin-only.

Новые проекты видны в `/projects`, создание — `/studio/new`, редактор —
`/studio/<id>`. Код, превью и медиа раскрываются явно. Ошибочный JSON сохраняется
черновиком, последнее корректное превью помечается происхождением. CAS
`expectedVersion` отличается от номера сохранённой `revision`; параллельные
операции не должны затирать локальный текст/его исходный токен. История и
зафиксированные задания сохраняются. Обновление рейтинга по стабильным ID
меняет текущий проект, но не frozen inputs старого задания. Личные и 30
встроенных пресетов содержат только оформление/абстрактные слоты.

Сайт запускается `npm run dev`, очередь — отдельным `npm run studio:worker`.
Текущие команды SDK используют Node с `--env-file-if-exists` (проверено на
22.23.2). Не держите общий daemon во время интеграционных тестов: он может
перехватить их задания. Для отдельного проверочного задания используйте
`npm run studio:worker -- --once --job JOB_ID`.

Повторяемая настоящая MCP-проверка:

```bash
node scripts/verify-studio.mjs --actor you@example.com \
  --project PROJECT_ID --kind clip --seconds 3 \
  --output storage/studio-verification/my-run
```

Драйвер требует явного актора и ровно один `--project`/`--document`, использует
только scoped CLI, пишет доказательства в новый каталог. Он не фиксирует
черновик существующего проекта; обычная синхронизация источника при чтении
остаётся активной. SHA-256/размер сверяются с настоящими MCP-байтами. Код 2
означает, что результат превышает 12 MiB и требует аутентифицированного
скачивания на сайте; это не подтверждение download. Проверочный аккаунт,
ассеты и ответы держите в игнорируемом `storage/`; пароли не печатайте и не
коммитьте, исходные пользовательские проекты не меняйте.

Обязательные итоговые проверки — `npm test`, `npx tsc --noEmit`, `npm run build`
после последних исправлений, плюс настоящий MCP/CLI, просмотр реальных кадров,
декодированный звук и живой сайт. Не объявляйте parity по типам/юнитам или
метаданным. Точные результаты и оставшиеся проверки — в
[журнале приёмки](.ai/phases/phase-20-verification.md); итог фазы 20 на 4251b02:
965/965 тестов (71 файл), TypeScript и production build прошли, существенные
замечания финального ревью закрыты. Прежний рецепт проверки находится в
[`.claude/skills/verify/`](.claude/skills/verify/SKILL.md).
