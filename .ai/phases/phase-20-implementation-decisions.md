# Решения при реализации AI Video SDK

Дополнения и интерпретации согласованной продуктовой/технической спецификации,
в порядке принятия. Они не меняют выбранный объём фичи.

1. Источник автоматически обновляет текущую композицию; поставленные задания и MP4 остаются неизменяемыми. Для нового MP4 потребуется новое задание.
2. Ограничения модальностей внешнего клиента сообщаются явно и сами по себе не блокируют структурно корректный рендер. Если запрос требует содержательной проверки изображения/звука, агент должен получить эту возможность и не заявлять о непроведённой проверке.
3. Новые проекты используют Studio; прежние остаются доступны без миграции и удаления. Цена — временное существование двух интерфейсов.
4. Использован существующий checkout в отдельной ветке, чтобы сохранить локальные данные и открытый сайт. Цена — этот checkout остаётся на feature-ветке до ручного переключения.
5. Авторская подпись `caption` отделена от исходного `label`. Это сохраняет оформление при смене рейтинга; цена — одно дополнительное поле SDK.
6. Автоматические карточки асимметричных групп имеют одинаковые размеры. Намеренно отличающиеся размеры задаются явными локальными настройками/free layout.
7. Хранение проектов и устойчивый worker разделены на самостоятельные этапы реализации и ревью. Цена — дополнительные проверочные этапы, без изменения пользовательского объёма.
8. Живой Player использует нативное непрерывное воспроизведение и асинхронную коррекцию; офлайн-рендер остаётся покадровым. Цена — возможные краткие отклонения живого воспроизведения; порог коррекции не объявляется жёсткой гарантией максимального рассинхрона.
9. Помимо консервативного извлечения пресета из проекта разрешён явный media-free `VideoPreset`. Так автор сохраняет универсальный текст без копирования содержания; цена — второй строго проверяемый вариант входа сохранения пресета.
10. Долгие URL-импорты включены в общую устойчивую очередь отдельным этапом. Цена — отдельный worker-процесс и дополнительное ревью; прежние DownloadJob не мигрируются.
11. До явного действия скрываются и визуальный предпросмотр, и сырой JSON с возможными ответами. Цена — дополнительное нажатие для открытия SDK.
12. Технические бюджеты ограничивают входы, разворачивание, время, heap/cache и публикацию результата. Они не объявляются общим пределом OS RSS или жёстким пределом временного диска кодировщика; Windows teardown не считается проверенным. Цена — эксплуатационные ограничения описаны в контракте24, проверена текущая macOS-среда.
13. Файлы Vitest запускаются последовательно из-за общей SQLite и глобального тяжёлого слота. Явные конкурентные сценарии остаются конкурентными. Цена — более долгий полный прогон.
14. Replace/patch/apply используют общий приватный примитив записи; receipt семантической операции проверяется до чтения изменяемого состояния. Цена — общий слой идемпотентности, который нужно сохранять при развитии API. Невалидный по схеме сырой черновик заменяется целиком, без молчаливого возврата к head.
