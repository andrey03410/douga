# План

**Цель:** из сохранённой ревизии студии за секунды получить ролик: ссылка
`/watch/<токен>` без входа и шапки, и один офлайн-`.html`. MP4 и классические
конструкторы остаются как были.

**Подход:** чистые функции плеера и нарезки отдельно от Prisma, чтобы их
гонять без базы. Публикация закрепляет снимок уже сохранённой ревизии и не
коммитит черновик. Файл собирает esbuild в один IIFE и кладёт внутрь только
вырезанные окна. Каждая задача начинается с красного теста. Решения — в
[tech.md](tech.md), продукт не переоткрываем.

## Задачи

- [ ] **1. Модель плеера и нарезки.** Файлы: `src/watch/model.ts`,
  `src/watch/model.test.ts`. Тесты: главы (первый кадр `roundId`, иначе
  `participantId`; сцена ответа не даёт вторую главу; интро без обоих не
  глава); ⏮ дальше 1 с от начала главы возвращает к ней, иначе к предыдущей,
  на первой — к 0; ⏭; ±5 с с упором в 0 и конец; `sharedAudioTagCount`
  не меньше 5 и не меньше максимума пересечений cue; разбор клавиш и отказ,
  когда фокус в поле ввода или стрелки на `range`; таймер скрытия 2500 мс
  только во время игры и не во время «загрузки», на паузе панель видима;
  перепись `src`/`posterSrc` плана на `/api/watch/<token>/media/<hash><ext>`
  без `/api/studio`, `/api/arts` и путей `studio/`; окна нарезки с запасом
  0,5 с и сдвиг `offsetFrames`; копия файла целиком, если хвосты короче 0,5 с;
  размер HTML из длин частей; отказ на 400 МиБ и на 500 000 000 символов
  base64 одного ассета; предупреждение с 80 МиБ; `Content-Disposition` для
  `.html`. Готово, когда `npx vitest run src/watch/model.test.ts` зелёный
  и серверные модули этот файл не импортируют `remotion`.

- [ ] **2. Публикация и защита снимка.** Файлы: `prisma/schema.prisma`
  (`StudioPublication`, `StudioExportCache`), `src/server/studio/publication.ts`,
  `src/server/studio/types.ts`, `src/server/studio/index.ts`,
  `src/server/studio/jobs.ts`, `src/server/studio/revisions.ts`,
  `src/server/studio/projects.ts`, `src/server/users.ts`,
  `src/integration/studio-publication.integration.test.ts`.
  После схемы: `npx prisma db push && npx prisma generate`.
  Тесты на реальной SQLite: опубликовать сохранённую ревизию (серверный
  черновик не коммитится и в ссылку не попадает); обновить — тот же токен,
  новый снимок и новая ревизия; повторное обновление без новой ревизии не
  плодит снимки; снять и опубликовать снова — новый токен, старый не находится;
  чужой пользователь получает `NOT_FOUND`; роль без `media:upload` —
  `FORBIDDEN`; удаление последнего задания и `deleteStudioSnapshot` не
  уничтожают снимок публикации; после снятия снимок без заданий уходит;
  `deleteStudioRevision` опубликованной ревизии — `REVISION_IN_USE`;
  `deleteStudioProject` и `deleteUser` с публикацией проходят без ошибки
  внешнего ключа, строка публикации исчезает; проект с заданием по-прежнему
  отвечает `JOB_IN_USE`. Готово, когда этот файл тестов зелёный.

- [ ] **3. Публичная страница и медиа.** Файлы: `src/middleware.ts`,
  `src/app/layout.tsx`, `src/app/watch/[token]/page.tsx`,
  `src/app/api/watch/[token]/media/[file]/route.ts`,
  `src/server/studio/watch-public.ts`, при необходимости общий mime из
  `src/server/studio/http-media.ts`,
  `src/integration/studio-watch.integration.test.ts`.
  Тесты: гость по токену получает план только с публичными URL и название;
  в JSON нет `document`, путей `files` и `/api/studio`; медиа снимка отдаётся
  200 и 206, суффиксный Range `bytes=-N` — последние байты, `Content-Range`
  верный; файл не читается целиком (`readFile` не используется на этом пути);
  чужой hash, путь с `..` и снятый токен — 404 с тем же смыслом, что и
  несуществующий; middleware на `/watch/...` помечает запрос так, что layout
  не рисует шапку, на `/projects` маркер не ставится. Страница без токена
  показывает «Ролик снят с публикации» и не зовёт `currentUser` ради редиректа.
  Готово, когда тесты зелёные, а ответ медиа идёт через `streamStudioFile`.

- [ ] **4. Оболочка плеера.** Файлы: `src/watch/WatchPlayer.tsx`,
  `src/watch/standalone.tsx` (точка монтирования для файла, без сборки),
  стили страницы просмотра, `src/remotion/StudioVideo.tsx`
  (`pauseWhenLoading` только у `<Img>`), `src/app/watch/[token]/page.tsx`
  подключает плеер. Тесты: существующие тесты студийного кадра не ломаются;
  отдельный тест не требуется сверх модели из задачи 1, поведение панели
  доказывается вживую (пункт 7 в tech.md). Готово, когда страница отдаёт
  плеер с обложкой ▶, своими контролами (▶/⏸, полоса и время, звук, полный
  экран, главы ⏮/⏭), клавишами Space ←/→ F M PageUp/PageDown, скрытием
  через 2,5 с и индикатором «загрузка»; на паузе панель остаётся;
  `numberOfSharedAudioTags` берётся из модели; клик ▶ вызывает `play` с
  событием; полный экран запрашивается у обёртки; кнопка полного экрана
  не рисуется без `document.fullscreenEnabled`; плеер вписан в экран
  (`100dvh`, касания не меньше 44 px). `StudioPreview` и классические
  композиции не меняются.

- [ ] **5. Файл `.html` и квота нарезки.** Файлы: `src/server/studio/export-html.ts`,
  `src/server/studio/export-slice.ts`, шрифты Arimo 400/700 и лицензия
  Apache-2.0 в `src/watch/fonts/`, `package.json` / `package-lock.json`
  (прямая `esbuild@0.28.0`), `next.config.mjs`
  (`serverComponentsExternalPackages`), маршруты оценки и скачивания в
  `src/server/studio/http.ts`, `src/server/users.ts` (байты кэша в
  `studio.bytes` и потолок 512 МиБ для роли без `render:run`),
  `src/integration/studio-export.integration.test.ts`.
  Тесты на крошечном ролике с картинкой, коротким видео и звуком, который
  использует не весь файл: оценка совпадает с длиной ответа скачивания;
  в HTML нет `src="http`, `href="http`, `url(http`, `fetch("http`, есть
  inline-скрипт без `type="module"` и `data:` шрифта; скачивание без
  публикации не создаёт `StudioPublication` и не коммитит черновик;
  повторная оценка не перекодирует (кэш по ревизии); кусок звука короче
  исходного трека, когда окно — это фрагмент; роль `user` упирается в
  `EXPORT_QUOTA_EXCEEDED`, админ — нет; удаление проекта стирает кэш.
  Серверный модуль экспорта не импортирует `remotion` (граница
  `server-boundary.test.ts`). Готово, когда эти тесты зелёные, а файл
  собирается потоком, без одной строки на весь ролик.

- [ ] **6. Студия и кабинет.** Файлы: `src/app/studio/[id]/StudioWorkspace.tsx`,
  `src/app/account/AccountManager.tsx`, `src/app/api/account/publications/route.ts`,
  список публикаций в `src/server/users.ts` или `publication.ts`.
  Тесты: HTTP списка отдаёт только публикации владельца, размер равен
  `snapshot.bytes`, снятие из кабинета удаляет строку и после этого
  публичный токен мёртв. Кнопки заданий по-прежнему гаснут на грязном
  буфере. Блок «Ролик без рендера» рядом с ними предупреждает, но не гаснет,
  если есть несохранённые правки и при этом есть сохранённая ревизия.
  «Обновить» видно только когда сохранённая ревизия новее опубликованной.
  Готово, когда тест списка зелёный, а в студии есть опубликовать, копировать,
  открыть, обновить, снять и скачать с размером.

- [ ] **7. MCP.** Файлы: `src/mcp/studio-tools.ts`, `.env.example`, `README.md`.

  Готово, когда тест зелёный и переменная описана в `.env.example` и README.

## Живые проверки

Список и критерий каждого пункта — в [tech.md](tech.md), раздел
«Как доказать готовность». Доказательства класть в
`storage/verification/24-html-player/`. Тройка строго
`npm test` → `npm run build` → `npx tsc --noEmit` после последних правок.
Перед `npm run build` проверить порт 3000 и не останавливать чужой сервер.
Проверочные аккаунт и проект — свои, в `storage/`, чужие проекты не менять.
