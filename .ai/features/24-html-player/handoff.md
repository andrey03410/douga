# Передача исполнителю (Cursor, скилл `goal`)

Владелец передаёт стадии «техника → вливание» в Cursor. Ниже — текст для `/goal`.
Технические вводные лежат в [tech.md](tech.md), продуктовые решения — в [product.md](product.md).

## Промпт

```text
/goal Доведи задачу 24 «HTML-плеер — ролик без рендера» в репозитории Douga от технической стадии до вливания в main, полностью автономно.

КОНТЕКСТ
- Ветка feat/24-html-player, папка задачи .ai/features/24-html-player/. Начни с README.md задачи, затем brief.md, product.md, tech.md.
- Процесс — скилл feature (.claude/skills/feature/SKILL.md), проверки — скилл verify (.claude/skills/verify/SKILL.md), правила проекта — AGENTS.md. Прочитай их целиком до начала работы.
- Владелец разрешил автономный режим только для этой задачи. Его слова записаны в brief.md, раздел «Автономный режим». Гейты «техника ок» и «принято» пропускаются: решения по развилкам принимаешь сам и записываешь в tech.md в формате T01… (вопрос → варианты → рекомендация → решение с причиной).
- Продукт утверждён (product.md, P01–P16), его не меняй. Если решение технически невыполнимо, выбери ближайший вариант, запиши причину в tech.md и сообщи в итоговом отчёте.

ГРАНИЦЫ
- HTML — дополнительный способ получить ролик. MP4-рендер остаётся и работает как раньше, его не убирай и не прячь.
- Только студия AI Video SDK. Классические конструкторы (VideoProject, PickerVideo, TopVideo, /projects/<id>, /tournaments/<id>/render) не трогай. Их удаление — будущая задача 25 (P14), её не заводи и не начинай.
- Не добавляй новых эффектов в StudioVideo. HTML должен играть ровно то, что уже рендерится в MP4.
- Не меняй поведение MP4-рендера. Любая правка src/remotion, src/video или src/lib меняет engineId: проверь, что студийный рендер после неё по-прежнему проходит.
- Не печатай и не коммить пароли и токены. Тестовые аккаунты и данные держи в storage/. Чужие проекты и медиа владельца не меняй: для проверок заведи своего пользователя и свой проект.

ЧТО СДЕЛАТЬ (по стадиям feature, каждая стадия — коммит и сдвиг stage в README.md задачи)
1. Техника: дополни tech.md. Раздел «Исходная система» — только то, что сам увидел в коде; сверь вводные агента с кодом и исправь неверное. Прими решения T01–T11 (там рекомендации агента) и добавь свои развилки, перечисли меняемые зоны. Внешние API (Remotion Player, Next.js, браузерные ограничения file:// и Fullscreen) сверяй с документацией, а не с памятью. Коммит docs(24): tech decisions.
2. План: plan.md с задачами, файлами, тестами и критерием «готово». Последняя задача — «Знания». Коммит docs(24): plan.
3. Реализация через TDD, коммиты по задачам в conventional-стиле (feat(studio): …). Нужно:
   - публикация последней сохранённой ревизии проекта по неугадываемой ссылке: опубликовать, обновить (та же ссылка), снять; новая публикация после снятия — новая ссылка;
   - публичная страница просмотра без входа и без шапки сайта; плеер Remotion с обложкой и ▶, своими контролами (▶/⏸, перемотка со временем, звук, полный экран, главы-раунды/позиции с ⏮/⏭), клавишами Space, ←/→ (±5 с), F, M, PageUp/PageDown; контролы и курсор прячутся через ~2,5 с без движения, на паузе видны всегда; при недогрузке медиа — пауза с индикатором «загрузка»;
   - публичная раздача медиа только из снимка опубликованной ревизии, с поддержкой Range, без чтения файла целиком в память;
   - «Скачать .html»: один самодостаточный файл (плеер, план, шрифты, нарезанные фрагменты медиа), который играет с диска (file://) без интернета; размер показывается до скачивания; работает и без публикации ссылки;
   - кнопки в студии рядом с рендером и предупреждение о несохранённых правках; список публикаций в /account с размером и снятием;
   - права: любой автор с media:upload; файлы публикаций учитываются в его квоте;
   - удаление проекта и аккаунта снимает публикации без ошибок внешних ключей;
   - MCP-инструмент, который публикует или обновляет публикацию и возвращает ссылку;
   - телефон: базовая поддержка (ролик вписан в экран, контролы по касанию, полный экран где браузер даёт).
4. QG по verify. Тройка после последних правок строго в порядке: npm test → npm run build → npx tsc --noEmit. Перед build проверь порт 3000 (lsof -nP -iTCP:3000 -sTCP:LISTEN): чужой сервер не останавливай без спроса. Живые проверки и доказательства — список в tech.md, раздел «Как доказать готовность». Цифры, команды и пути к доказательствам (storage/verification/24-html-player/…) запиши в verify.md.
5. Ревью: отдай дифф ветки свежему ревьюеру-субагенту, существенное исправь, остальное с причиной запиши в verify.md. После исправлений снова тройка.
6. Знания: обнови карточки .ai/map/ всех затронутых зон (как минимум studio-sdk.md, roles.md, mcp.md; render.md и media.md — если менялись), добавь строку в .ai/history.md.
7. PR: git push -u origin feat/24-html-player, gh pr create с заголовком «24: HTML-плеер — ролик без рендера»; в теле ссылка на папку задачи, что сделано, итоги QG и «Что посмотреть руками». В README.md задачи pr и stage: review, затем stage: merged и дата, коммит docs(24): merged, push, gh pr merge <pr> --merge --delete-branch, git switch main && git pull --ff-only.

КОГДА ОСТАНОВИТЬСЯ И НЕ ВЛИВАТЬ
- Красный QG, который не удаётся исправить, или неисправленное существенное замечание ревью: не вливай, опиши владельцу, что сломано, с выводом команд.
- Вопрос, который нельзя решить из кода, документов и product.md: спроси владельца.

ГОТОВО, только когда доказано всё:
- tech.md, plan.md и verify.md закоммичены, stage в README.md задачи — merged;
- тройка зелёная после последних правок, числа тестов записаны;
- каждая проверка из раздела «Как доказать готовность» в tech.md выполнена и записана с доказательством; если какую-то выполнить невозможно, причина записана в verify.md и названа в итоговом отчёте, а готовность по ней не объявляется;
- PR влит в main, ветка удалена, локальный main обновлён.
```

## Как запустить

- Cursor работает в этом же чекауте (`/Users/gel/my_projects/douga`) на ветке `feat/24-html-player`.
  Ворктри по правилам проекта не нужен: в нём нет `.env`, `storage/`, `prisma/dev.db` и `node_modules`.
- Перед запуском остановить свой `npm run dev` и `npm run studio:worker` или предупредить Cursor,
  что они работают: тесты делят `prisma/dev.db`, а общий воркер перехватывает задания тестов.
- Если Cursor запускается в облаке, ветку сначала нужно запушить: сейчас она только локальная.
