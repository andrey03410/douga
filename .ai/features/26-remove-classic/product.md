# Продуктовые решения

Стадия пройдена в автономном режиме ([brief.md](brief.md#автономный-режим)). Решения принимал
агент, владелец их не подтверждал. Догадки о смысле постановки описаны в
[brief.md](brief.md#как-агент-понял-постановку).

## Цель

Сейчас у Douga два способа сделать видео. Классика — это ручной топ, турнирный топ и пикер
со своими страницами, API, MCP-инструментами, тремя композициями Remotion и рендером внутри
процесса Next. Второй способ — AI Video SDK с одной композицией `Studio`, устойчивой очередью
и MCP `video_*`. Из 30 прежних MCP-инструментов 14 собирают классику, рядом лежат 30 новых
`video_*`, и агент путается. Правка в `src/remotion` задевает три композиции сразу.

После задачи способ один: SDK. Видео собирает агент через MCP. Владелец вручную делает только
рейтинг, то есть проходит турнир на сайте. Своё видео агент собирает и без турнира.

## Сценарии

1. **Топ по турниру.** Владелец загружает архив, проходит сравнения, на странице результатов
   выбирает N и при желании переставляет позиции. Дальше одно из двух:
   - просит агента: «сделай видео по турниру „Опенинги 2024“». Агент находит турнир через
     `video_source_list`, создаёт SDK-проект с источником-турниром, оформляет его, проверяет
     кадры и рендерит (`video_job_start kind:"render"` под админом);
   - жмёт «Создать видео через SDK →» и получает SDK-проект. Его можно отдать агенту по id
     или открыть в студии.

   Рейтинг потом можно поменять: SDK-проект сам подтянет новый порядок (`reconcileSource`).
2. **Свой топ агента.** Владелец просит: «сделай топ-10 моих любимых OST из Shikimori».
   Агент сам выбирает позиции и порядок. Звук берёт через `import_youtube_audio` или
   `import_local_media`, картинки — через `import_shikimori_poster`. Затем собирает документ
   с `source.kind: "manual"`, у участников `rank` и привязки медиа пула. Фрагменты выбирает
   режимом `snippet` (`active`, `manual`, `full`), проверяет и рендерит.
3. **Пикер.** Как сейчас в скилле `/picker`: только SDK (`video_*` и скрипты скилла).
   Скилл классику уже не использует, это проверено по его файлам.
4. **Пул с сайта.** Владелец загружает файл, картинку по ссылке или звук с YouTube, ищет постер
   в Shikimori. Всё это теперь делается в кабинете, в блоке пула. Агент потом берёт медиа
   по `artId`.
5. **Смотреть и раздавать.** Без изменений: `/studio/<id>` — превью, история, задания,
   финальный MP4 для админа; публикация `/watch/<token>` и офлайн-`.html`.

## Решения

### P01. Что остаётся единственным путём к видео

- Варианты:
  - (а) AI Video SDK. Главный автор — агент через MCP `video_*`. Веб-студия `/studio/new` и
    `/studio/<id>` остаётся местом, где смотрят, проверяют, рендерят и публикуют;
  - (б) SDK только через MCP: веб-студию тоже убрать;
  - (в) оставить классику и только спрятать её от агента.
- Рекомендация: (а). Веб-студия — тот же документ, та же очередь и та же композиция `Studio`,
  второго конвейера она не создаёт. Без неё владелец не увидит превью и историю, не скачает
  MP4 и не опубликует ролик без агента. (в) не даёт ни одного рендерера, ни похудевшего кода.
- **Решение:** (а). Классика удаляется целиком. Веб-студия не меняется.

### P02. Путь «турнир → видео» на сайте

- Варианты:
  - (а) на странице результатов остаётся только «Создать видео через SDK →». Кнопка
    «Открыть прежний рендер» и панель «Рендер» со ссылкой на конструктор убираются. Под кнопкой
    одна строка подсказки: видео оформляет агент через MCP и находит турнир по названию;
  - (б) то же, но без подсказки;
  - (в) убрать и кнопку SDK: только агент.
- Рекомендация: (а). Кнопка уже есть, и она даёт проект, который можно передать агенту.
  Подсказка дешёвая и показывает новый путь там, где раньше стояла ссылка на конструктор.
  (в) отнимает у владельца быстрый путь без агента.
- **Решение:** (а).

### P03. Как агент сам делает топ

- Варианты:
  - (а) SDK-документ с `source.kind: "manual"`. Участников и `rank` задаёт агент, звук и картинки
    берутся из пула (`bindings` вида `pool`), фрагмент — через `settings.top.snippet`. Новых
    моделей и инструментов нет. Агенту дают инструкцию сервера и полный пример в `video_examples`;
  - (б) высокоуровневый инструмент вроде прежнего `set_top_items`: список позиций → готовый документ;
  - (в) MCP-инструменты, через которые агент создаёт турнир и сам проходит сравнения.
- Рекомендация: (а). SDK уже умеет ручной топ: у участника есть `media.audio` и `media.visual`,
  режимы фрагмента — `manual`, `full` и `active`. Активный фрагмент для звука из пула считается
  через `StudioAnalysis` (проверено в `src/server/studio/assets.ts`). (б) повторяет документ
  вторым API, а это та самая двойственность, от которой уходим. (в) бессмысленна: сравнения
  отражают вкус владельца, а не агента.
- **Решение:** (а). Приёмка — живой прогон: агент через настоящий MCP собирает свой топ
  минимум из трёх позиций с медиа пула и рендерит клип. Кадры и звук проверены.

### P04. Ручной топ на сайте

- Варианты:
  - (а) ручной путь на сайте — это турнир плюс ручная перестановка ↑↓ в результатах.
    Отдельной формы ручного топа нет;
  - (б) сделать в SDK новую форму «ручной топ без турнира».
- Рекомендация: (а). Формы ручного топа на сайте нет и сейчас: `CreateProjectForm.tsx` уже
  удалён, классический ручной топ создавали только API и MCP. Владелец сказал, что
  «создание топа остаётся ручным в интерфейсе», то есть так, как есть. Топ без турнира делает
  агент (P03).
- **Решение:** (а). Это догадка о смысле слов владельца, см. [brief.md](brief.md#как-агент-понял-постановку).

### P05. Данные и файлы классики

В `prisma/dev.db` владельца на 2026-11-02:

| Что | Сколько |
|---|---|
| проекты `VideoProject` | 17 |
| раунды, карточки и блоки пикеров | 332, 1719 и 485 |
| треки плейлистов | 34 |
| конфиги и позиции топов (`RenderConfig` и `RenderItem`) | 6 и 84 |
| задания рендера (`RenderJob`) | 19 |
| `storage/renders/` | 1,9 ГБ, 27 MP4, из них 383 МБ во временном `tmp/` |

- Варианты:
  - (а) удалить таблицы и файлы без копий;
  - (б) перед удалением таблиц один раз скопировать `prisma/dev.db` в `storage/backups/`,
    а MP4 удалить без копии;
  - (в) скопировать и базу, и MP4.
- Рекомендация: (б). Владелец просил удалить данные и MP4, поэтому (в) противоречит брифу.
  Копия базы весит около 86 МБ и нужна не для переноса. Таблицы удаляются на общей `dev.db`
  ещё в ветке, до вливания: тесты и QG идут на этой базе. Если PR не примут, `main` без копии
  останется без своих таблиц. Копии базы в `storage/backups/` делали и раньше
  (`before-studio-*.db`). Код копию не читает.
- **Решение:** (б). Медиа пула не трогаем, даже если ими пользовалась только классика.
  Удаляется тик классики `storage/assets/tick.wav`: у студии свой `studio/builtin/tick.wav`.

### P06. Раздел «Рендеры» в кабинете

- Варианты:
  - (а) убрать раздел без замены. Результаты студии остаются в `/studio/<id>`, в кабинете
    остаются сводка «Студия» и список «Публикации»;
  - (б) заменить раздел списком финальных MP4 студии со скачиванием.
- Рекомендация: (а). В разделе только классические `RenderJob`, после удаления он пуст.
  Список MP4 студии — новая функция, к удалению классики она не относится.
- **Решение:** (а). Список MP4 студии в кабинете записан в хвосты.

### P07. Импорт в пул с сайта

Табы «Файлы · Ссылка · Shikimori» и вставка `Ctrl+V` живут в `ImportSources`. Его открывает
только модалка медиа классических конструкторов (`ArtGalleryModal`). В кабинете пул можно
смотреть, переименовывать и удалять, а добавлять нельзя. Если удалить конструкторы как есть,
загрузка в пул с сайта пропадёт.

- Варианты:
  - (а) перенести `ImportSources` в блок пула кабинета `/account`. Модалка с выбором и кропом
    удаляется;
  - (б) оставить импорт только агенту: MCP и импорт студии по ссылке;
  - (в) перенести импорт в студию `/studio/<id>`.
- Рекомендация: (а). Владелец сказал, что пул остаётся, а загрузка файлов с диска через браузер
  у агента недоступна: MCP видит только папки `MCP_LOCAL_MEDIA_DIRS`. Кабинет уже показывает пул,
  импорт там на своём месте. Кроп в SDK задаётся в документе (`CardStyle.crop`), отдельная
  модалка не нужна.
- **Решение:** (а).

### P08. Что видит агент в MCP

- Варианты:
  - (а) убрать 14 классических инструментов. Остаются 11 `shikimori_*`, 5 инструментов пула
    (`list_pool`, `import_shikimori_poster`, `import_youtube_audio`, `list_local_media`,
    `import_local_media`) и 30 `video_*`. Серверу добавляется инструкция (`instructions` в MCP)
    с тремя рецептами: топ по турниру, свой топ, пикер. В описаниях инструментов пула сказано,
    как `artId` становится привязкой SDK. Слова LEGACY уходят;
  - (б) только убрать инструменты.
- Рекомендация: (а). Владелец хочет, «чтобы ему было удобно». Инструкция приходит агенту при
  подключении, и ему не нужно восстанавливать путь по 46 описаниям. Имена оставшихся
  инструментов не меняются: на них опираются скрипты `/picker` (`list_pool`,
  `import_shikimori_poster`, `import_youtube_audio`, `shikimori_*`).
- **Решение:** (а).

### P09. Старые адреса

- Варианты:
  - (а) `/projects/<id>`, `/tournaments/<id>/render` и удалённые API отвечают 404;
  - (б) редиректы: страницы ведут на `/projects` и `/tournaments/<id>`.
- Рекомендация: (а). Владелец просил «без совместимости». Ссылками пользуется только он.
- **Решение:** (а). `/projects` («Мои видео») остаётся: там список SDK-проектов и подсказка
  по MCP. Раздел «Ранее созданные проекты» исчезает.

### P10. Что считается провалом, даже если всё формально работает

- Агент через MCP не может довести до клипа хотя бы один из трёх сценариев: топ по турниру,
  свой топ, пикер.
- С сайта нельзя добавить файл в пул.
- Пострадали турниры (сравнения, undo, «ещё раунд», результаты, перестановка) или SDK-проекты,
  публикации и `/watch`.
- Из пула пропали медиа или их файлы.
- Остались осиротевшие куски классики: ссылки в навигации, кнопки, тексты, описания MCP,
  разделы README и карточек, которые ведут в никуда.

### P11. Старые рабочие папки роликов

В `.ai/production/` (вне git) лежат папки прошлых роликов, и разовые драйверы в некоторых из
них вызывают классические инструменты.

- Варианты:
  - (а) не трогать: это архив производства, его скрипты повторно не запускают;
  - (б) переписать их драйверы на SDK.
- Рекомендация: (а). Скилл `/picker` прямо запрещает копировать разовые скрипты прошлых роликов.
- **Решение:** (а).

## Не входит

- Перенос классических проектов в SDK. Без переноса — по брифу.
- Новые возможности SDK вместо того, что было только в классике. Например, «Старт отсюда»
  (выбор начала фрагмента на слух) и модалка кропа: в SDK старт и кроп задаются в документе.
- Список MP4 студии в кабинете (P06).
- MCP-инструменты для турниров (P03).
- Изменения в движке турниров, в SDK-документе, компиляторе и `StudioVideo`.
- Изменения веб-студии, публикации и `/watch`.
- Правка скилла `/picker`: классику он уже не использует.
