## Живые проверки

Сайт — `npm run dev` на :3000, аккаунт — `scripts/e2e-setup.mjs`.

- **Вход без учёта регистра.** Ввёл `E2E@Test.Local`, хотя аккаунт хранится как
  `e2e@test.local`. Вход прошёл и привёл на `/projects`; `/` тоже перенаправляет на `/projects`.
- **SSRF на сайте.** `POST /api/downloads` отвечает 400 с текстом «По этому адресу ходить
  нельзя…» для `127.0.0.1`, `[::1]`, `localhost` и `10.0.0.5`. Для несуществующего хоста —
  «Сайт по ссылке не найден». Заданий не создано. Публичный `https://example.com/` проходит
  гард: задание создано, статус `running`.
- **SSRF через настоящий MCP** (stdio, копия базы, `ssrf-mcp-live.mjs`). Рядом поднят
  «секретный» HTTP-сервис на loopback.
  - `import_youtube_audio` вернул текст отказа для всех форм адреса: `127.0.0.1`,
    `[::ffff:127.0.0.1]`, `[::ffff:7f00:1]`, `[::ffff:a9fe:a9fe]` (метаданные облака) и
    `2130706433`.
  - `video_import_start` вернул `BLOCKED_HOST` для `[64:ff9b::7f00:1]` и `169.254.169.254`.
  - Ссылку `http://example.com\@127.0.0.1:PORT/secret` схема нормализовала до
    `http://example.com/@127.0.0.1:PORT/secret`. Настоящий worker (`--once --job`) прогнал её

- **Турнир по HTTP.** `scripts/e2e-run.mjs` прошёл: 4 экрана `question` → `{ranked, rest}`,

## Ревью

Свежий ревьюер смотрел `git diff main...HEAD` только на чтение, обходы проверял экспериментом.

- **Критично, исправлено.**
  - IPv4-mapped IPv6 в hex-записи обходил гард во всех входах. WHATWG пишет
    `[::ffff:127.0.0.1]` как `[::ffff:7f00:1]`, а проверка искала только точечный хвост.
    Теперь IPv6 разбирается в 16 байт, mapped/compatible/NAT64/6to4 судятся по встроенному IPv4.
  - Студийный импорт отдавал yt-dlp сырую строку. Python `urlparse` читает
    `http://a.com\@127.0.0.1/` с хостом 127.0.0.1, а гард видел `a.com`. Теперь схема
    нормализует ссылку до `URL.href`.
- **Важно, исправлено.** `failStaleRenderJobs` мог пометить failed живой рендер в долгой фазе
  без прогресса: бандл, перекодирование длинного видео в `clipMode: full`. Теперь
  `withRenderJob` раз в минуту шлёт пульс. Финальные записи (`completeRenderJob`,
  `failRenderJob`) не оживляют удалённое или упавшее задание и не бросают P2025.
- **Мелочь, исправлено.**
  - При старых двойниках `Bob@x` и `bob@x` хозяин `Bob@x` не мог войти. Теперь
    `verifyCredentials` перебирает варианты, вход решает пароль.
  - MCP `get_project` отдаёт `invalidRounds`.
- **Оставлено:**
  - `verifyCredentials` не тратит bcrypt на несуществующий email, поэтому по времени ответа
    видно, есть ли аккаунт. Так было и раньше, а регистрация всё равно раскрывает
    существование аккаунта.
  - Текст «нужно минимум 2 блока» для раунда `single` совпадает с терминологией конструктора:
    плитки там называются блоками.
  - DNS-проверка в `startStudioImport` идёт до повтора по ключу идемпотентности. Повтор старого
    ключа на адрес, который стал приватным, вернёт `BLOCKED_HOST`, и это безопасный отказ.
  - У `lookup` нет своего таймаута, работают системные.
  - `downloadTitleStem` режет по code point и может разрезать ZWJ-эмодзи на границе 100
    символов. Заголовок при этом остаётся валидным.
