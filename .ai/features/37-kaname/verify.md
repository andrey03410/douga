# Приёмка Douga и Kaname

Проверка 23 ноября 2026 года использовала локальный Keycloak с отдельным realm, запущенный сервер Kaname с PostgreSQL и Douga на отдельной SQLite. Браузер Chrome проходил обычный вход, отправлял формы и работал с API от имени вошедшего человека. Три выданных назначения соответствовали владельцу и двум участникам. Производственные данные в проверке не участвовали.

## Quality gate

На коде `20d9396` команды выполнены в проектном порядке на отдельной базе. `npm test` прошёл 1719 тестов из 144 файлов за 389,72 секунды. Затем успешно завершились `npm run build` с предварительной сборкой HTML-плеера и `npx tsc --noEmit`. В журнале типизации ноль диагностических строк. Результаты команд сохранены в `storage/kaname-acceptance/final-test.log`, `final-build.log`, `final-types.log`.

## Вход, аккаунт и отзыв

- Все три пользователя прошли authorization code flow. В запросе Keycloak проверены state, nonce и S256. Возврат шёл на `/api/auth/callback/keycloak`. Реальная проверка выявила замену хоста 127.0.0.1 на localhost в NextRequest. После сохранения исходного origin обмен кода завершился успешно.
- В режиме Kaname Auth.js объявлял только Keycloak. Токен старого несвязанного локального администратора получил 403. Две учётные записи с одним отображаемым логином получили разные локальные id в интеграционном тесте.
- В браузере владелец через Kaname назначил действующему участнику роль администратора Douga и поднял квоту до четырёх проектов и 2 000 000 000 байт. Та же сессия показала изменение, создала четвёртый проект, получила 403 на серверное превью. В локальной модерации отсутствовали действия над владельцем.
- Владелец отозвал назначение площадки. Существующие веб-сессия и HTTP MCP с валидным персональным токеном получили 403. Уже подключённый stdio MCP отказал на следующем вызове. Реальный воркер получил ранее сохранённое тестовое задание и завершил его как `failed/FORBIDDEN` до запуска движка. Исходное назначение восстановлено через Kaname.
- В отдельной проверке реальный HTTP-обработчик MCP с действующим токеном и недоступным адресом Kaname вернул 503 и `KANAME_UNAVAILABLE`.

## HTML, владение и счётчики

- Четыре конкурентных HTTP-запроса на создание получили 201, 201, 201, 429. Три запроса на публикацию получили 200, 200, 429. Другой участник получил 404 на чтение чужого проекта. Снятие ссылки освобождает слот.
- Пользователь открыл публичный HTML-плеер и скачал готовый HTML. HTTP MCP прочитал список проектов и отклонил серверный still. Для композиции с оригинальными PNG и WAV показ по ссылке дал 200, а оценка оффлайн-файла, требующая нарезки, вернула `FORBIDDEN`. В кэше нарезки появилось 0 файлов.
- Интерактивная публикация работала без построения кадров, создала 0 серверных заданий и заняла слот общей квоты. Линейная и интерактивная ссылки вместе заняли оба слота. Следующая ссылка стала доступна после освобождения слота.
- При 128 114 байтах оригиналов отчёт этого сценария учёл 904 787 байт с ревизиями, шрифтами и документами. Отдельный тест конкурирующих загрузок на последних 10 байтах квоты принял одну и отклонил вторую. Принудительное снижение квоты до нуля сохранило возможность снятия публикации.
- При занятых трёх проектах и двух ссылках отчёт вернул 15 435 байт и один активный день. Токен обратного направления получил 401. Неизвестный subject возвращает нули. Ни опрос отчёта, ни heartbeat воркера не регистрируют активность.

## Локальное управление

Владелец открыл управление Douga и приостановил участника. Его прежняя веб-сессия стала недействительной (401), HTTP MCP получил 403, а публичная страница показала сообщение о снятой публикации. У публичного плеера штатный статус этой страницы — 200. После проверки владелец возобновил локальный доступ. Серверный тест проверил также запрет на модерацию владельца и отказ обычному участнику в модерации другого аккаунта.

## Ревью

Координатор экосистемы обнаружил локальный потолок, перекрывавший повышение центральной квоты, и смешение недоступности центра с отзывом прав. Исправления проверены тестами, живой сменой назначения и отдельным вызовом HTTP-обработчика с недоступным upstream.

Дополнительное замечание ревью касалось роли владельца. Douga сверяет любой ответ с ролью overlord с закреплённым локальным KANAME_OWNER_SUBJECT. Тест проверяет отсутствие пина, попытку повышения другого субъекта и положительный ответ для владельца. Отдельный процесс с реальным ответом центрального стенда подтвердил отказ при отсутствии или несовпадении пина. На копии прежней схемы аддитивный db push сохранил старую строку администратора, автоматически созданных связей Kaname — 0.
