# Задача 5: страницы раскадровки и рецептов

2026-11-06. UI реализован отдельными страницами; server/MCP/domain не менялись.

## Маршруты

- `/studio/:id/storyboard`: SSR читает `owned` и только title/version/revision.
  `getStudioProject` и reconcileSource не вызываются.
- `/studio/recipes?project=:id&sourceId=:source`: авторизованная галерея.
- В основном workspace — две ссылки с `target="_blank" rel="noopener"`.
  Локальный editor buffer не заменяется. При dirty показано, что другие страницы
  читают сохранённый документ. На странице создания добавлен вход в рецепты.

## Раскадровка

Три вкладки: весь ролик, замечания, до/после. Доступны выбор серверного черновика
или ревизии, сегмента, конкретной сцены, страницы и размера листа 6/12/24.
Сравнение — с ревизией либо запомненным inspection job.

Из POST storyboard берётся durable job. Статус обновляется с backoff 0.9–5 с,
после 26 запросов автоматическое ожидание прекращается с явной кнопкой продолжения.
Есть пауза обновления и отмена самой задачи. Session storage сохраняет ID и параметры
последней задачи: после возврата во вкладку результат/очередь возобновляются.

Готовый результат содержит общий PNG и отдельные кадры с открытием/скачиванием,
человеческим состоянием, таймкодом и абсолютным frame. Missing/partial не выдаётся
за успешное покрытие. Показываются origin, before origin, формат, сцены этой страницы,
остальные сцены, номер страницы и технические подробности в раскрытии.
При пагинации используются параметры первого запроса, а не изменённые элементы
формы. Различие contentHash любой стороны прерывает продолжение старого листа.

Плеер использует штатный StudioVideo. Кнопка кадра/замечания делает seekTo(actualFrame)
и pause. Переход доступен только при совпадении contentHash текущего Player и origin
листа. Старый лист остаётся доступен, но не подменяется свежим плеером. Исторические
и новые результаты подписаны отдельно; смена серверной версии отмечает stale.

Замечания загружаются страницами по 20, со счётчиками, evidence и честными
notChecked по motion/audio/contrast. Есть выбор реальных suggestion IDs.
Перед apply требуется готовая раскадровка того же contentHash как вариант «до»;
затем CAS review-apply, повторная проверка, обновление плана и новый compare job
с compareJobId прежнего результата. Никаких commit/publication вызовов нет.
После успешной записи notice появляется до последующих read-запросов: ошибка
повторной проверки не скрывает уже выполненное изменение черновика.
Deep review предлагает реальные клипы со звуком и ручное обновление их статуса.

## Рецепты

GET recipes?all=1 с фильтрами kind/format/style/query, выбор деталей и живой пример
через GET recipe/plan. Картинки — authenticated versioned preview endpoint;
при отсутствии эталона показано, что он не подготовлен/недоступен, с переходом к
живому примеру. Поддельные скриншоты не генерируются.

В рецепте указаны плотность, время, материалы и языки; contentForm раскрывается
с required/optional/constraints/slot IDs и копированием предметного примера.
Создание проекта использует штатный presetId; sourceId передаётся только топу.

Список owned проектов пагинируется. До трёх отмеченных рецептов примеряются
POST recipe/try на реальных материалах с expectedVersion, без записи черновика.
Результаты имеют подписи origin и показываются рядом в штатных плеерах.
Применение — отдельный CAS POST project/preset с понятным предупреждением о
несохранённом локальном тексте и возможном конфликте открытого редактора.
Новый/обновлённый проект и его раскадровка открываются отдельными ссылками.

Все новые TSX/CSS отформатированы локальным Prettier. Изменения общего workspace
ограничены ссылками; проверки, зеркалящие JSX, не добавлялись.

Живая проверка браузером и общий QG делегированы основной интеграции. Этот агент
не запускал/не останавливал dev server и не управлял портами, чтобы не нарушать
общую `.next`. После коммита UI заморожен для скриншотов основного агента.

Ограничения UI: selector ревизий показывает последние 50 (номер для сравнения
можно ввести вручную); deep clips обновляются явно; художественная оценка и
прослушивание остаются действиями владельца/осматривающего агента.
