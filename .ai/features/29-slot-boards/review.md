## Important

### R1. Ненайденный явно назначенный звук не делает OST-доску неготовой

- Место: `src/video/board-compiler.ts:117–120`.
- Воспроизведение: создать `board.sort-quiz`, первому участнику назначить `media: { audio: "missing" }`, не добавлять binding/manifest и вызвать `compileVideo(document)`.
- Факт из read-only domain probe: `ready: true`, ошибок нет, primary cue отсутствует. Ветка возвращается до `resolveAsset`, поэтому не возникает `ASSET_NOT_FOUND`. Явное назначение картинки в поле `audio` также молча игнорируется вместо `ASSET_KIND_MISMATCH`.
- Достижимость в студии: `resolveAssets` в `src/server/studio/assets.ts:236–238` пропускает ключ без binding; затем `evaluate` объединяет его диагностику с диагностикой `compileVideo`. Другой проверки наличия обязательного звука здесь нет. В результате музыкальную викторину можно подтвердить и отрендерить без назначенного вопроса-звука.
- Ожидание: явно назначенное participant audio разрешается и валидируется штатным `resolveAsset`; молчаливый отказ допустим для отсутствующего неявного аудио у картинки, но не для ошибочного явного назначения. Разделить проверку явного audio и fallback из visual.

### R2. Настройка зацикливания участника теряется в звуке доски

- Место: `src/video/board-compiler.ts:121`.
- Воспроизведение: у участника `media: { visual: "clip", audio: "clip" }`, `settings: { card: { loop: true } }`; manifest содержит видео с `durationSec: 0.5`, `hasAudio: true`; `revealSec` по умолчанию 1.5.
- Факт из read-only domain probe: reveal длится 45 кадров при 30 fps, primary audio — только 15 кадров, `loopFrames: null`. `addAudio` не получает `loop`, поэтому обрезает cue по длине источника. Видеоряд через `compileMedia` получает `loop: true` и продолжает повторяться без звука.
- Последствие: заданный автором loop не работает в OST/видеокандидатах доски, звук заканчивается раньше активного прослушивания, после чего преждевременно прекращается и ducking музыки. Общий picker передаёт `local.card?.loop` в тот же `addAudio` (`blocks.ts:469`).
- Исправление: передавать эффективную настройку `loop` и проверять длительность/loopFrames аудио вместе с видеорядом.

### R3. Личный пресет доски извлекает skeleton из чужой коллекции и не создаёт пригодный новый выпуск

- Место введения нового пути: `src/video/board-presets.ts:43–49`; связь с `src/video/presets.ts:318–321`.
- Воспроизведение: `d = createVideoDocument({kind:"board", presetId:"board.kmk"})`; `p = extractVideoPreset(d, {id:"mine", name:"Mine"})`; затем `createVideoDocument({kind:"board", preset:p})`.
- Факт: извлечённый `p.skeleton` равен `{roundCount:0, cardsPerRound:4, groupCount:0}`, хотя KMK имеет три карточки в раунде. Новый документ содержит ноль участников и раундов; компиляция возвращает `BOARD_EMPTY`.
- Более сильный сценарий с реальным новым контентом: передать тому же пресету шесть новых участников. Фабрика создаёт по четыре карточки на три слота вместимости 1 и бросает `BOARD_SLOT_FULL` и `BOARD_ASSIGNMENT_MISSING` в каждом раунде. Оба сценария воспроизведены read-only probe.
- Причина: extraction использует `doc.source.rounds`, но board-раунды находятся в `scene.board.rounds`; новая factory затем доверяет получившемуся skeleton. Это ломает переиспользование личного пресета для серии роликов (P09/T04).
- Исправление: извлекать board skeleton из данных доски, не сохраняя сами назначения/участников; проверить создание нового документа как без явных counts, так и с новым списком участников.

### R4. Личный пресет нескольких board-сцен нельзя применить даже обратно к исходному документу

- Место: `src/video/board-presets.ts:83–88`, вызов для каждой сцены в `src/video/presets.ts:286`.
- Воспроизведение: взять валидный v2 KMK-документ, добавить в тот же сегмент вторую board-сцену с уникальными IDs сцены, слотов, раундов, карточек и действий. Извлечь личный пресет и вызвать `applyVideoPreset(document, preset)`.
- Факт из read-only domain probe: исключение `Duplicate stable ID: board-slot-1` (также `board-slot-2`, `board-slot-3`), стек проходит через common application `presets.ts:411` и итоговый `parseVideoDocument` v1. Каждая сцена при extraction заново нумерует слоты с 1. Common application использует `scenes: []`, поэтому переноса исходных уникальных IDs до валидации не происходит.
- Последствие: допустимый составной board-дизайн сохраняется в личный пресет, но этот пресет нельзя применить; stable-ID контракт документа глобальный и проверяет слоты всех сцен вместе (`schema.ts:645`).
- Исправление: канонические ID слотов должны быть уникальны в пределах всего пресета, а сопоставление при apply должно учитывать ту же схему. Счётчики медиа в `extractBoardDesign` также локальные: при исправлении namespace нужно сохранить независимость разных media slots между сценами и custom nodes.
