# Технические решения

Приняты агентом в автономном режиме 2026-11-06 на основании принятого продукта.

## Исходная система

Прочитаны `types.ts`, `schema.ts`, `compiler.ts`, `context.ts`, `blocks.ts`, `nodes.ts`,
`audio.ts`, `assets.ts`, `presets.ts`, `patches.ts`, `resource-limits.ts`,
`StudioVideo.tsx`, `studio-frame.ts`, MCP `studio-tools.ts` и карточки studio-sdk,
render, mcp, dev-env. Документ v2 компилирует сегменты в локальные документы,
затем сдвигает сцены и звук. Renderer уже умеет карточки, текст, картинки,
таймеры и анимации x/y/scale/opacity; новый отдельный renderer не нужен.
Пресеты не содержат участников и реальных привязок. Вид проекта в БД — строка.

## T01. Модель и версия

- Варианты: типизированный board в документе; произвольные custom-узлы;
  отдельный игровой runtime.
- Решение: новый kind/block `board`. `scene.board` содержит версионированное
  `version:1` описание: slots, rounds с cards и actions, правила и presentation.
  Участник остаётся в `source.participants`, карточка — его отдельное появление.
  Новые factory-документы досок используют v2, `board` сочетается с top/picker/custom.
- Причина: собственные данные и диагностика, прежний детерминированный IR.

## T02. Чистая логика

- Решение: `board-state.ts`: `createBoardState()`,
  `applyBoardAction(board, state, action, cards): BoardState`,
  `resolveBoard(board, participants): BoardResolution`.
  Функции не меняют вход. Ошибки действий типизированы (`BoardRuleError`).
- Размещение: одна карточка находится максимум в одном слоте; capacity отсутствует —
  вместимость не ограничена. `place` требует резерв, `move` — размещённую карточку;
  `swap` атомарен, `replace` атомарно возвращает заменяемую карточку в резерв,
  `remove`, `lock`, `unlock` явны. Блокировка запрещает перенос/удаление/замену/обмен.
- Бюджет — сумма стоимости размещённых карточек; удаление и замена возвращают стоимость.
  Невалидное действие не изменяет состояние. Стоимости неотрицательны.
- Накопление сохраняет доску. Раунды сбрасывают её, если не задан carry.
  Явное очищение слотов действует на границе раунда. Действия могут ссылаться только
  на уже введённые карточки; старый резерв после сброса недоступен.
- `requireAllAssigned` опционален; в драфте невыбранные кандидаты допустимы.
  Повтор участника внутри раунда по умолчанию запрещён; появления в разных раундах
  имеют разные ID. Слепой рейтинг использует по одной карточке на раунд и lockOnPlace.

## T03. Компиляция и подача

- Решение: `board-compiler.ts` строит обычные CompiledScene/CompiledNode.
  Задание → показ кандидатов → таймер → последовательные действия → итог.
  Фазы настраиваются в секундах; движение интерполируется через обычные keyframes.
- presentation: together/sequential, отложенное до конца раскрытие результата,
  скрытие подписей/изображений до распределения, акцент на активном кандидате,
  обзор и дополнительный проход по слотам. Пустые слоты видны в первом кадре.
  rows/grid/free, нормализованные rect слота, подписи осей для матрицы.
- Имена и картинки будущих кандидатов не попадают в ранние сцены.
  Видеоряд размещённого кандидата удерживает кадр; звук играет только при активном показе.
  Звуки слота/действия — существующие ассеты. Музыкальная дорожка получает стандартный ducking.
- Board-сцены включают метаданные событий, пригодные для привязки AudioCue
  к появлению/размещению/переносу/замене/итогу по стабильным ID.

## T04. Пресеты, фабрика и патчи

- Решение: восемь семейств × wide/vertical/square: tier, kmk, smash-pass,
  blind-rank, draft, sort-quiz, alignment, budget-draft. Короткий ID без формата
  разрешается как wide. Factory принимает готовое board-описание или создаёт
  заполненный демонстрационный сценарий из skeleton.
- Личный пресет сохраняет слоты, правила и подачу, удаляет раунды/действия/участников,
  переводит медиа в абстрактные slots. Применение сохраняет назначения только при
  совместимой структуре слотов; иначе PRESET_INCOMPATIBLE, без молчаливой потери.
- Патчи поддерживают стабильные boardSlot/boardRound/boardCard/boardAction ID.
  Полная замена коллекций — через валидацию документа.

## T05. Бюджеты и совместимость

- Решение: preflight считает развёртку board до выделения снимков состояния;
  после компиляции действуют общие лимиты сцен, узлов, звука и длительности.
  Произвольный JS/CSS/URL в описании не появляется.
- Старые top/picker планы не меняются. Board-медиа участвуют в сборе ключей,
  защите используемых файлов, frozen snapshot и экспорте штатным путём.
- Новых страниц/игровых сессий/таблиц БД нет. Существующие списки подписывают kind
  «Доска», чтобы проекты, созданные SDK, не назывались пикерами.

## Затронутые зоны и доказательства

- studio-sdk: схемы, чистые правила, компилятор, пресеты, factory, assets, patches.
- mcp: schema/catalog/examples и создание проекта с board-presets.
- render: живые MP4/PNG с обзором и действиями, декодированное аудио.
- Проверка: targeted TDD, полная тройка npm test → build → tsc после последних правок;
  настоящий MCP, worker и frozen snapshot на отдельных проверочных данных.
