## Strengths

- Чистый синхронный компилятор получает реальный измеритель через явную
  зависимость. Fontkit, файловая система и проверка хэшей остаются на сервере;
  строки, координаты runs и выбранные faces сериализуются в IR. Renderer не
  запускает новый fitter. Это соответствует основному архитектурному контракту.
- Каталог замкнут: семь семейств, двенадцать стилей, шесть тем, восемь ролей;
  произвольный CSS и font URL не попадают в документ. Настоящие italic faces
  явно отделены, синтетика выключена, провайдер проверяет pinned bytes/hash.
- Учтена смешанная совместимость: метаданные authored layers не принимают
  DEFAULT_SETTINGS за сохранённые overrides, оптические эффекты имеют отдельные
  границы, legacy-ветка рендерера сохранена, наследование и сбросы локализованы.
- Ресурсы шрифтов закрепляются отдельным ledger, переиспользуют одинаковые
  variable-файлы, входят в снимок и engineId. Public watch переписывает URL через
  allowlist снимка; offline встраивает выбранные физические файлы и лицензии и
  учитывает их фактический base64 размер. Прежний принудительный font CSS обходит
  новые текстовые поддеревья.
- Применение темы повторно использует writeDraft с атомарным CAS и receipts.
  Панель проекта учитывает dirty/conflict, acceptRemote сохраняет локальный
  буфер. Диагностический child использует общую heavy lease, heartbeat,
  ограничение времени и очистку временных файлов.
- Ветка содержит целевые доменные, ресурсные, renderer, сервисные и сквозные
  тесты. По их исходникам проверяются реальные Fontkit widths, повреждение
  ресурсов, JP fallback, старые пресеты, принадлежность проекта, CAS и replay;
  результаты прогонов в этом ревью не заявляются.

### Important (Should Fix)

#### F31-01. Rich text без отдельного typography не получает измеритель

- Место: `src/server/studio/assets.ts:561`, `src/video/typography-compiler.ts:179`.
- Вход: прежний документ без ключей `typography`, где только одна надпись заменена
  на `{runs:[{text:"Имя",color:"yellow"}]}`. Этот вариант проходит новую схему.
- Причина: серверный usesTypography ищет только truthy поле с именем typography,
  а доменный resolveTypography включает новый путь и по наличию rich runs.
  Сервер передаёт undefined вместо measureText, поэтому возникает
  TEXT_LAYOUT_REQUIRED и layout не появляется.
- Последствие: допустимый локальный rich opt-in нельзя подготовить, зафиксировать,
  экспортировать или отрендерить через штатный сервис, хотя чистый compiler с
  провайдером поддерживает его. Нарушены P04/P11 и согласованный opt-in контракт.
- Исправление: учитывать rich text при определении потребности в измерителе;
  проверить сервисный путь rich-only текста, badge и подписи карточки.

#### F31-02. Read-only inspect может создать ревизию через source reconciliation

- Место: `src/server/studio/typography.ts:195` и `:315`; связанный путь —
  `src/server/studio/projects.ts:176` (readProject).
- Состояние: проект привязан к турниру, а версия/состав источника после последнего
  чтения изменились. Агент вызывает video_text_inspect, в том числе с прежним
  expectedVersion.
- Причина: оба вызова getStudioProject могут выполнить reconcileSource,
  evaluate, cas и addRevision(reason="source"). Первый из них стоит до проверки
  expectedVersion, поэтому даже отказ VERSION_CONFLICT уже имеет побочный эффект.
- Последствие: заявленное диагностическое чтение меняет head/draft/version и
  создаёт ревизию. Это прямо противоречит P08: диагностический PNG не создаёт
  коммит, ревизию или обычное задание и не изменяет документ.
- Исправление: читать принадлежащую актору сохранённую строку проекта и её view
  без reconciliation; повторно проверять версию тем же read-only способом.

#### F31-03. Резерв динамических чисел не совпадает с реально рисуемой строкой

- Место: `src/video/typography-compiler.ts:430`, `src/remotion/TypographyText.tsx:104`;
  второй триггер — `src/video/typography-compiler.ts:267`.
- Вход 1: timer либо text-counter с числом `1000`, Arimo 48 px, minimum 24 px,
  maxLines=2, обычным wrap и рамкой 60×120 px. Резерв четырёх цифр помещается в
  две строки; compiler может объявить такой узел готовым. Renderer подставляет
  всё текущее значение только в первую линию и игнорирует остальные линии.
  Четыре цифры выходят за измеренную двухзначную ширину и могут обрезаться рамкой.
- Вход 2: text-counter с текстом `+100` либо `0001`. Ветка перечисления значений
  использует String(i), отбрасывая плюс и исходные ведущие нули, тогда как
  counterText по окончании анимации возвращает исходный текст. Финальное значение
  может оказаться шире резерва даже при wrap=none.
- Последствие: ready=true перестаёт гарантировать подгонку динамического текста;
  PNG/MP4 и Player выходят за зафиксированную геометрию. Нарушены P05/P11.
- Исправление: согласовать одно- либо многострочный контракт числового резерва с
  renderer и включать в измерение все формы вывода, включая исходный финальный
  текст. Проверить counter/timer/progress и повторную подгонку в fitGroup.

#### F31-04. Пагинация inspect не ограничивает строки внутри одного узла

- Место: `src/server/studio/typography.ts:227`; связанный путь —
  `src/video/typography-layout.ts:281` и `src/mcp/typography-tools.ts:40`.
- Вход: одна допустимая надпись с текстом `"a\n".repeat(4999)` и обычной политикой
  overflow=error. Она укладывается в бюджет 10000 графем и может храниться как
  проблемный черновик.
- Причина: layout для error оставляет все примерно 5000 строк, inspect включает
  textLayout целиком даже при limit=1, а MCP сериализует этот объект и как text,
  и как structuredContent. limit/cursor ограничивают только число узлов.
- Последствие: один элемент выдаёт тысячи строк; обычный limit=20 может вернуть
  многомегабайтный подробный JSON, мешающий штатному агентскому сценарию. Это
  конкретное нарушение P08 «не выдаём тысячи строк за один вызов» и требования
  bounded MCP/API из плана.
- Исправление: ограничить line/run детали общим бюджетом ответа, сообщать полное
  количество и признак сокращения/продолжение. Для полного проблемного кадра
  использовать отдельный PNG путь, не выдавая весь IR по умолчанию.

#### F31-05. Личный пресет теряет rich-оформление подписи карточки

- Место: `src/video/presets.ts:328`; связанное новое sanitizing text/badge — `:319`.
- Вход: custom card с label
  `{runs:[{text:{bind:"participant.label"},color:"yellow",weight:400}]}`.
  Владелец сохраняет оформление как личный пресет и применяет его к другому видео.
- Причина: text/badge rich runs очищаются с сохранением оформления, но любая
  подпись card безусловно заменяется на `{bind:"participant.label"}`.
- Последствие: цвет, жирность, курсив и декорация фрагментов карточки исчезают
  при save→apply. P07 обещает сохранять типографику в личных пресетах;
  domain-report отдельно заявляет сохранение оформления фрагментов.
- Исправление: очищать приватное содержимое rich label по тому же принципу,
  сохраняя его run styles и безопасные привязки. Проверить полный round trip.

### Оставшиеся Important

**F31-04, остаток:** `src/server/studio/typography.ts:277` разворачивает полный
layout, заменяя только lines. Полный массив missing и строка reservedText уходят

позволяют получить ответ порядка мегабайта из маленького документа. Числовой
