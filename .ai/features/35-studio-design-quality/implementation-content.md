# Предметное заполнение: группы, медиа раунда и тиры

Задача 3 плана реализована в назначенных файлах. Полный QG и живая визуальная
приёмка остаются за интеграцией всей задачи 35; ниже — целевые проверки этой части.

## Контракт короткой формы

- `participants[]`: дополнены `subtitle`, `tier`, `kind:audio|video|image`.
  Эти три поля принимают `null`, который удаляет значение; `merge` сохраняет
  неназванные поля, `replace` сохраняет только явно переданное содержимое и прежние
  настройки оформления.
- `rounds[].groups:[{id,label?,cardIds?}] | null`: `merge` обновляет группы по ID,
  сохраняет неназванные группы и их настройки. `cardIds` обязательны для новой
  группы и при `replace`; ссылки указывают на `rounds[].cards[].id`.
  `null` убирает группы. Неверная ссылка, повторный ID или одна карточка в двух
  группах дают адресную ошибку до изменения документа.
- `rounds[].answerGroupIds:string[] | null`: явный ответ группами. Существующий
  `answerParticipantIds` продолжает задавать ответ карточками. Каналы независимы:
  `null` очищает только соответствующий канал; ответ не придумывается.
- `rounds[].musicAssetId` и `backgroundAssetId`: ID собственного материала пула,
  либо `null`. Музыка записывается в каноническое `round.music`; `null` становится
  `music:null`, что также отключает наследуемую музыку в окне раунда. Фон записывается
  в `round.background`, `null` удаляет назначение раунда. Неназванные при `merge`
  назначения сохраняются; при `replace` очищаются. Общие bindings не перезаписываются.
- `kind:"board", tiers:[{id,label?,participantIds?,color?,background?}]`:
  при `replace` и для нового тира нужны `label` и `participantIds`; `merge`
  сохраняет неназванные тиры и поля. Перемещение участника выражается явным
  изменением списков исходного и целевого тира. Повторное распределение одного
  участника и неизвестные участники отклоняются.

`tiers` и низкоуровневые `boards` не смешиваются в одной операции. Семантические
тиры применяются к единственной сцене существующей accumulate-доски без carry
и бюджета. Адаптер генерирует слоты, карточки и обычные `place`-действия, сохраняет
row focus/дизайн доски, повторно использует ID карточек/действий и ограничивает
новые ID до 200 символов. Коллизии с пользовательскими ID обходятся.
Нового игрового движка и полей канонической схемы нет.

## Сервер и атомарность

Новый `src/server/studio/content-assets.ts` проверяет ownership и канал каждого
явно назначенного pool asset, включая участников, которые сейчас не показаны.
Запросы идут пачками по 500 ID, чтобы размер документа не превышал лимит
SQLite bind-параметров. Визуальный канал принимает image/video; звуковой — audio
либо video со звуком. Обычный `evaluate` продолжает проверять реальные файлы.

Root подключил `validateStudioContentAssets` внутри callback `writeDraft`:
после receipt replay/expectedVersion, до построения и записи черновика. Старые
проверки ссылок, реальная компиляция, CAS и транзакция не обходятся.
`src/server/studio/content.ts` не потребовал отдельного изменения: он использует
расширенную SDK-схему и прежний адаптер ошибок.
