## Уточнения

Перед брифом агент исследовал вопрос и пробовал переход на копиях. Итог он показал владельцу,
после чего пришло «да, переводи оба проекта»:
- Prisma 8 (самая новая) — кандидат `8.0.0-rc.30`, переписанная ORM с новым API запросов.
  SQLite в ней экспериментальный: `orm init` его не предлагает, `contract infer` не
  поддерживается, а даты из баз Prisma 5–7 (целые миллисекунды) не читаются —
  `RUNTIME.DECODE_FAILED`. Нет `increment`, `$extends`, опций транзакций. Переход на 8 сейчас заблокирован.
- Prisma 7.10.1 — последняя стабильная, её будут поддерживать 18 месяцев после выхода 8.
  Prisma 5 уже без патчей. Пробный переход Douga на копии: тесты 913/913, сборка и типы зелёные.
- Ловушки, найденные при пробе:
  - адаптер по умолчанию пишет даты ISO-строками, и сравнения со старыми числовыми датами ломаются;
  - относительный `DATABASE_URL` (`file:./dev.db`) в Prisma 7 отсчитывается от корня, а не от `prisma/`;
  - `Prisma.dmmf` больше не экспортируется, на нём стоит тест дрейфа клиента.
- Догадка агента: «самая последняя» для владельца — самая последняя, на которую можно
  перейти без блокеров, то есть 7.10.1. К 8 вернёмся, когда она выйдет и SQLite станет стабильным.

## Трек

`tech` — меняется инфраструктура доступа к базе, поведение сайта, воркера и MCP не меняется.

## Успех

- Douga работает на `prisma`/`@prisma/client` 7.10.1 с адаптером SQLite, версии закреплены точно.
- `.env` владельца и его `prisma/dev.db` подходят без правок: тот же файл базы, даты остаются
  целыми миллисекундами, аренды воркера и сроки сравниваются верно.
- Обязательная тройка зелёная. Живые проверки проходят: сайт под существующей сессией,
  настоящий MCP, задание студии в воркере.
- `npm audit --omit=dev` не находит уязвимостей в пакетах Prisma.
