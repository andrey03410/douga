# Техника

Автономный режим: решения принимает агент, владелец может пересмотреть любое.

## Исходная система

- `prisma` и `@prisma/client` `^5.22.0`, генератор `prisma-client-js`, клиент лежит в `node_modules/.prisma`.
  В `datasource` указан `url = env("DATABASE_URL")`. Каталога миграций нет, схема
  применяется через `db push` ([dev-env](../../map/dev-env.md)).
- [`src/lib/db.ts`](../../../src/lib/db.ts) — `new PrismaClient()` без опций, в dev клиент кэшируется в `globalThis`.
  Этим клиентом пользуются сайт (Next), `scripts/studio-worker.ts`, `scripts/studio-render-child.ts` и MCP-сервер.
- `.env` владельца: `DATABASE_URL="file:./dev.db"`. Prisma 5 отсчитывает относительный путь от
  папки схемы, поэтому это `prisma/dev.db`. `vitest.config.ts` передаёт абсолютный путь.
- Даты в `prisma/dev.db` хранятся целыми миллисекундами: так пишет Prisma 5 для SQLite.
- Тип `Prisma` и типы моделей импортируются из `@prisma/client` в шести серверных файлах
  (`accounts.ts`, `tournament-segments.ts`, `studio/{imports,jobs,projects,shared}.ts`).
- Около 40 интерактивных транзакций `prisma.$transaction(async (db) => …)`. Сырой SQL:
  `$queryRaw` в `accounts.ts`, `$executeRaw` в `studio/publication.ts` и `studio/export-slice.ts`.
  `increment` — в `studio/worker.ts`.
- [`src/lib/prisma-client.test.ts`](../../../src/lib/prisma-client.test.ts) ловит забытый `generate`,
  сверяя схему с `Prisma.dmmf`.
- `scripts/e2e-setup.mjs` и `scripts/clean-test-data.cjs` создают клиент сами через `datasources`.
- `@auth/prisma-adapter` объявлен в зависимостях, но нигде не импортируется: вход идёт через
  Credentials без адаптера.
- Карточка dev-env фиксирует: в Prisma 5 интерактивные транзакции внутри процесса идут
  строго по очереди, у SQLite одно соединение.

## Решения

### T01. Какая версия

- Варианты: Prisma 8 (`8.0.0-rc.30`, тег `latest`); Prisma 7.10.1; остаться на 5.
- **Решение агента:** 7.10.1, версии закреплены точно, без `^`. Восьмёрка — другая ORM,
  и её SQLite не читает наши даты ([бриф](brief.md)). Точная фиксация нужна, потому что `npm i prisma@latest`
  и подсказка CLI ведут на восьмёрку. Пакеты: `prisma`, `@prisma/client`,
  `@prisma/adapter-better-sqlite3`, `@prisma/driver-adapter-utils` (типы для обёртки, T05).

### T02. Генератор и где лежит клиент

- Prisma 7 убирает `prisma-client-js`: новый генератор `prisma-client` требует `output`.
- **Решение агента:** `output = "../src/generated/prisma"`, папка в `.gitignore`, импорт —
  `@/generated/prisma/client`. Нужен `importFileExtension = "ts"`: тогда `scripts/*.mjs` загружают
  клиент обычным `node` со встроенным снятием типов (Node ≥ 22.18, у владельца 22.23.2). Next,
  tsx и vitest такие импорты понимают.
- `generate` больше не запускается сам после `db push` и `npm install`. Поэтому
  `postinstall: prisma generate`, а `db:push` = `prisma db push && prisma generate`.
  `npm run dev` по-прежнему начинается с `generate`.

### T03. Адрес базы и `.env`

- Prisma 7 запрещает `url` в схеме (P1012): адрес для CLI задаётся в `prisma.config.ts`, а для
  рантайма — адаптеру. `.env` CLI больше сам не читает. Относительный `file:` путь теперь
  считается от рабочей папки, а не от `prisma/`, и `file:./dev.db` владельца указал бы на пустой
  `./dev.db` в корне.
- Варианты: попросить владельца поправить `.env` и шаблон на `file:./prisma/dev.db`;
  сохранить старое правило отсчёта у себя.
- **Решение агента:** сохранить правило. Новый модуль `src/lib/database-url.ts` превращает
  `DATABASE_URL` в абсолютный `file:` адрес: относительный путь считается от `<cwd>/prisma/`,
  как в Prisma 5, без переменной берётся `prisma/dev.db`. Модулем пользуются
  `prisma.config.ts` (загружает `.env` через `process.loadEnvFile`, явно заданные переменные
  важнее) и `src/lib/db.ts`. `.env` и `.env.example` не меняются.
- Рантайм открывает файл с `fileMustExist: true`: неверный путь даёт ошибку, а не
  молча созданную пустую базу. Новую базу по-прежнему создаёт `prisma db push`.

### T04. Формат дат

- Адаптер по умолчанию пишет `DateTime` ISO-строками. В базе с числовыми датами SQLite считает любое
  число меньше любой строки: аренда воркера, сроки заданий и сортировки по дате ломаются.
- **Решение агента:** `timestampFormat: "unixepoch-ms"` — целые миллисекунды, как писала Prisma 5.
  Тест проверяет `typeof()` колонки и сравнение `gt`.

### T05. Одно соединение и транзакции

- Адаптер держит одно соединение на процесс и упорядочивает только транзакции между собой.
  Запрос вне транзакции, пришедший, пока она открыта, выполнился бы внутри неё и откатился бы
  вместе с ней. Это проверено на Asobiba: запись другого запроса терялась.
- **Решение агента:** перенести из Asobiba обёртку `sqliteAdapter`
  (`src/lib/sqlite-adapter.ts`). Это FIFO-очередь на соединение: транзакция держит её до
  commit или rollback, остальные запросы ждут. Это новое поведение: в Prisma 5 пул из нескольких
  соединений пускал чтения рядом с пишущей транзакцией (поправлено после ревью, сначала здесь
  ошибочно стояло «одно соединение»). Цена — пока идёт длинная транзакция (`createTournament`
  сохраняет файлы архива внутри неё), запросы процесса ждут. Для личного сайта это
  приемлемо. Второе соединение только для чтения или вынос сохранения файлов из транзакции —
  в «Хвосты». Правило: внутри `$transaction(async (db) => …)` — только `db`. Запрос через
  общий `prisma` там ждёт до таймаута транзакции (5 с), а после отката выполняется сам. Все
  транзакции проверены аудитом на такие вызовы, итог — в [verify.md](verify.md).
- Клиент один на процесс и в продакшене: `next start` вычисляет `db.ts` в каждом слое сборки,
  а отдельные клиенты дали бы отдельные соединения с синхронным ожиданием блокировок
  друг друга (найдено ревью).
- Тест, сначала красный: внешняя запись во время чужой транзакции, которая откатывается, сохраняется.

### T06. Блокировки между процессами

- Сайт, воркер и MCP — разные процессы на одном файле. `better-sqlite3` синхронный:
  ожидание чужой блокировки (busy timeout 5 с, как у Prisma 5) теперь держит event loop
  процесса, а не поток движка.
- Варианты: перевести базу в WAL; укоротить таймаут; оставить.
- **Решение агента:** оставить режим журнала и таймаут. WAL меняет файл базы владельца:
  появляются `-wal` и `-shm`, а ручная копия одного `dev.db` в `storage/backups/` может
  потерять свежие записи. Конфликты бывают при длинных транзакциях с файловой работой.
  Они редки для личного сайта, и их список даёт аудит из T05. Записать в грабли dev-env.

### T07. Тест дрейфа клиента

- `Prisma.dmmf` в Prisma 7 не экспортируется.
- **Решение агента:** сверять схему с `Prisma.ModelName` и `<Model>ScalarFieldEnum` — публичными
  списками колонок клиента. Поля-связи колонок не имеют, их тест пропускает.

### T08. Скрипты

- `e2e-setup.mjs` и `clean-test-data.cjs` строят клиент с адаптером и тем же форматом дат.
  `.cjs` становится `.mjs`: клиент Prisma 7 только ESM. Обёртка T05 скриптам не нужна:
  они делают запросы последовательно.

### T09. Лишняя зависимость

- **Решение агента:** удалить неиспользуемый `@auth/prisma-adapter`. Это адаптер Auth.js к
  Prisma, его типы привязаны к старому клиенту. Код его не импортирует.

### T10. Рабочее место

- Скилл `feature` советует основной чекаут. Сейчас в папке Douga открыты ещё четыре сессии
  Claude с MCP-серверами Douga. `npm install` с Prisma 7 поменял бы `node_modules` под
  их процессами и тестами.
- **Решение агента:** ворктри `../douga-28-prisma-7`, в нём копия `.env` и `prisma/dev.db`,
  `storage` — симлинк на основной. Тесты и живые проверки идут на копии базы,
  dev-сервер ветки — на свободном порту со своим `.next`. После вливания основной чекаут
  нужно `npm install`-нуть, а запущенные процессы Douga (dev, воркер, MCP) — перезапустить.
