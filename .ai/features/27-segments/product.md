# Продуктовые решения

> **Черновик.** Кандидаты в объём ждут выбора владельца. Решений `P…` пока нет:
> развилки ниже — предложения агента.

## Цель

Роли разделены ([brief.md](brief.md#уточнения)):

- **Человек делает топ.** Турнир и его результаты — источник данных для ролика.
- **Агент монтирует ролик** через SDK рендера.

Сейчас топ — один сплошной список. Человек не может разделить его на части
«Эпизод 1 … Эпизод 8» так, чтобы у каждой были своё название, свой порядок и свой размер.
Задача:

1. Дать человеку удобный механизм дробить **один** топ на сегменты и готовить их данные для ролика.
2. Научить SDK собирать ролик из сегментов.
3. Добавить визуальные средства и удобства монтажа, которыми агент оформит такой ролик.

## Что есть сейчас (по коду)

**Сторона человека — турнир**

- Загрузка ZIP: треки сортируются по имени файла. Название и исполнитель берутся из тегов.
  Папки архива, альбом и обложка из тегов не сохраняются.
- Сравнения идут по всему турниру сразу. Послушать трек можно только на экране сравнения.
- Результаты: один размер топа `topSize` и перестановка стрелками ↑↓ по одной позиции.
  Нельзя прослушать трек, поправить название, исключить трек, оставить комментарий.
- Кнопка «Создать видео через SDK» ведёт в `/studio/new?sourceId=…`.

**Сторона SDK — документ**

- `VideoDocument` v1: один `source`, в нём `participants` и `rounds`. Сцена с `repeat`
  проходит по **всем** участникам или раундам.
- Интро и аутро уже делаются сценами `custom`.
- Топ и пикер в одном документе формально допустимы, но участники у них общие и место
  у участника одно на весь ролик.
- `reconcileSource` берёт top-N рейтинга. У участника только название, исполнитель и место,
  картинки у аудиотрека нет.
- Главы `/watch` безымянные: «Позиция 1, 2…» или «Раунд 1, 2…».

## Сценарии

1. **Эпизодный топ.** Человек грузит OST Umineko одним архивом с папками по эпизодам.
   Сегменты появляются сами, и человек проходит сравнения. Затем ставит в каждом эпизоде размер
   топа и подписи и жмёт «Создать видео». Агент монтирует: интро → «Эпизод 1» с топ-5 → … → аутро.
2. **Большой топ блоками.** Топ-50 одного турнира разрезан на блоки «50–41», «40–31»…
   с общей сквозной нумерацией.
3. **Смешанный ролик.** Агент добавляет после топа свой сегмент-пикер «а теперь выбери сам».
   Человек делает только топ, пикер собирает агент.

## Кандидаты в объём

Номера с буквой блока, чтобы можно было ответить «А1, А2, Б3». Размер — грубая оценка работы.

### Блок А. Сегменты в топе (человек)

Механизм дробления одного топа.

| № | Идея | Зачем | Размер |
|---|------|-------|--------|
| А1 | Сегменты из папок архива | ZIP с папками «Эпизод 1/…» сразу даёт сегменты с этими названиями и порядком | мало |
| А2 | Ручная разбивка на странице турнира | Создать, назвать и переставить сегменты, разложить треки мультивыбором. Нужна для архива без папок и для исправлений | средне |
| А3 | Разбивка по альбому из тегов | Предложение «разложить по альбомам» одной кнопкой | мало |
| А4 | Сравнения только внутри сегмента | Каждый сегмент — свой мини-турнир со своим прогрессом. Порядок внутри эпизода честный, сравнений меньше | средне |
| А5 | Финал «лучшие из лучших» | После сегментов их победители (top-1 или top-K) сравниваются между собой и дают сегмент «Финал» | средне |
| А6 | Свой размер топа у сегмента | Топ-5 в одном эпизоде, топ-3 в другом | мало |
| А7 | Блоки по местам | Один общий рейтинг режется на главы «50–41», «40–31»…, нумерация сквозная | мало |
| А8 | Данные сегмента для ролика | Название, подзаголовок и картинка сегмента (постер эпизода из пула или Shikimori) | мало |
| А9 | Дозагрузка сегмента | Новый архив добавляется в готовый турнир отдельным сегментом: вышел новый эпизод или сезон | средне |

**Почему А4 по умолчанию** (рекомендация агента). В общем швейцарском турнире два трека одного
эпизода могут ни разу не встретиться, и топ-5 эпизода выйдет случайным. В мини-турнирах порядок
внутри сегмента точнее, а сравнений меньше: 80 треков одним турниром — около 280 пар,
8 сегментов по 10 — около 160.

### Блок Б. Топ удобнее (человек)

| № | Идея | Зачем | Размер |
|---|------|-------|--------|
| Б1 | Перетаскивание мест мышью | Вместо ↑↓ по одной позиции: в топ-50 стрелки мучительны | мало |
| Б2 | Прослушивание в результатах | Кнопка ▶ у позиции: проверить порядок перед роликом | мало |
| Б3 | «Лучший момент» трека | Отметка на экране сравнения или в результатах становится началом фрагмента в ролике | средне |
| Б4 | Правка названия и исполнителя | Кривые теги чинятся на сайте, а не в архиве | мало |
| Б5 | Обложка трека | Из тегов MP3 автоматически, замена картинкой из пула или Shikimori | мало–средне |
| Б6 | Комментарий к позиции | «Почему здесь»: агент показывает его второй строкой или озвучивает | мало |
| Б7 | Почётные упоминания | Отметить треки за пределами топа, агент делает из них отдельный быстрый блок | мало |
| Б8 | Исключить трек | Убрать дубль или мусор без перезагрузки архива | мало–средне |
| Б9 | Ручной топ без сравнений | Для маленького списка человек расставляет порядок сам | средне |
| Б10 | Топ из нескольких турниров | Готовые турниры собираются в один источник как сегменты | средне |

### Блок В. SDK и монтаж агентом

По словам владельца этот блок тоже входит в задачу.

**Основа.** Без неё сегменты из блока А до ролика не дойдут.

| № | Идея | Зачем | Размер |
|---|------|-------|--------|
| В1 | Сегменты в документе | Новая версия схемы. Источник отдаёт сегменты с названиями и местами внутри. Цель патча `segment`. Агент добавляет, копирует, переставляет и удаляет сегменты. Пресет красит все сегменты, сегмент переопределяет своё. Старые проекты — один сегмент, выглядят как раньше | много |
| В2 | Смешение форматов | Сегменты топа, пикера и свободные (интро, аутро) в одном ролике | средне |
| В3 | Заставка сегмента | Короткая «Эпизод 1» перед блоком, оформляется или выключается | средне |
| В4 | Главы по сегментам | `/watch` и офлайн-`.html` показывают названия сегментов | мало |

**Визуал и удобство монтажа**

| № | Идея | Зачем | Размер |
|---|------|-------|--------|
| В5 | Таймкоды для YouTube | Кнопка и MCP-инструмент отдают «00:00 Интро / 00:12 Эпизод 1 …» | мало |
| В6 | Раскрытие места | Сначала крупное «#3», затем карточка | средне |
| В7 | Итоговая таблица | В конце сегмента или ролика все места одной сеткой | средне |
| В8 | Лесенка | Раскрытые места копятся списком сбоку кадра | много |
| В9 | Длительность по месту | Верхние места звучат дольше по правилу, а не ручной расстановкой | мало |
| В10 | Вторая строка карточки | Показ комментария (Б6), альбома или «аниме · год» | мало |
| В11 | Очки турнира на карточке | «12 побед из 14» | мало |
| В12 | Блок почётных упоминаний | Быстрый показ треков из Б7 сеткой или вспышками | средне |
| В13 | Тизер в начале | Вспышки всех позиций без мест в первые секунды | средне |
| В14 | Фон из размытой обложки | Обложка участника на весь кадр под карточкой | средне |
| В15 | Обложка ролика | Отдельный кадр 1280×720 для превью YouTube | средне |
| В16 | Шортсы из сегментов | Сегмент рендерится отдельным вертикальным роликом | много |

Часть пунктов В выводит на экран данные из А и Б: В10 ← Б6, В12 ← Б7, В3 ← А8.
Если пункт из А или Б не берём, его пара в В теряет смысл.

### Рекомендация агента

- **Блок А:** А1, А2, А4, А6, А8 — ядро механизма. А5 и А7 стоит добавить: оба дешёвые
  и дают по новому сценарию. А3 и А9 можно отложить.
- **Блок Б:** Б1, Б2, Б4, Б5, Б6 — дешёвые и заметные. Б3 — самый полезный из средних.
  Б7–Б10 — по желанию.
- **Блок В:** В1–В4 обязательны. Из визуала больше всего работы в В8 и В16. Если задачу
  захочется облегчить, их первыми выносим отдельно.
- Если брать почти всё, задача крупная. Тогда в плане разобью её на этапы: данные турнира →
  мост в SDK → визуал. Каждый этап проверяется вживую.
