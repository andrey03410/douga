# Продуктовые решения

> **Продукт принят** владельцем 2026-11-05, дословно: «Да фиксируй все это в продуктовую
> сторону и принимай. остальное отдам другому агенту». Развилки `P…` приняты, как рекомендовал
> агент, объём — в разделе [«Объём»](#объём). Техника, план и реализация — у следующего агента.

## Цель

Роли разделены ([brief.md](brief.md#уточнения)):

- **Человек делает топ турниром.** Турнир и его результаты — источник данных для ролика.
- **Агент монтирует ролик** через SDK рендера. Он же может подготовить турнир по просьбе человека.

Сейчас турнир — один сплошной список, и ролик по нему — один блок. Задача:

1. Дать человеку удобно дробить **один** турнир на сегменты. Путей два: загрузить сразу
   несколько архивов или загрузить один архив и раздробить его потом.
2. Дать агенту вход: «вот OST Umineko, сделай 8 сетов в одном турнире». Агент создаёт турнир
   и раскладывает треки, а места в каждом сегменте человек определяет сам.
3. Научить SDK собирать ролик из сегментов. Добавить возможности, которые расширяют
   то, что агент может собрать.

## Что есть сейчас (по коду)

**Турнир**

- Форма создания принимает один ZIP. Треки сортируются по имени файла, название и исполнитель
  берутся из тегов. Папки архива, альбом и обложка не сохраняются.
- Сравнения идут по всему турниру сразу. Послушать трек можно только на экране сравнения.
- Результаты: один размер топа и перестановка стрелками ↑↓ по одной позиции.
- У MCP нет инструментов турнира. Агент умеет брать файлы с диска (`list_local_media`,
  `import_local_media` в пределах `MCP_LOCAL_MEDIA_DIRS`) и из YouTube, но только в пул.

**SDK**

- `VideoDocument` v1: один `source`, сцена с `repeat` проходит по **всем** участникам или раундам.
- Агент уже собирает из узлов многое сам. Пример — раскрытие места: свободная сцена с повтором
  по участникам, текст с привязкой `participant.rank`, затем узел `card` с `$participant`
  и задержкой. Карточка сама играет звук участника.
- Чего агент сделать не может:
  - взять картинку или звук текущего участника в обычный узел `image`/`video`/`audio`
    (там только ключ привязки);
  - разложить в одной сцене набор участников, который сам следует за рейтингом;
  - размыть картинку;
  - отрендерить часть ролика;
  - сделать кадр вне таймлайна.

## Сценарий: Umineko

**Вход владельца.**

1. Владелец создаёт турнир и бросает в форму 8 архивов. Форма показывает 8 сегментов
   с именами файлов, он переименовывает их в «Эпизод 1 … 8».
2. Другой путь: один архив с папками по эпизодам, и форма сама предлагает разбить по папкам.
3. Третий путь: один архив без папок. Тогда владелец раскладывает треки в редакторе разбивки.

**Вход агента.**

1. Владелец пишет агенту «вот OST Umineko в папке …, сделай 8 сетов».
2. Агент читает файлы и их теги, раскладывает треки по эпизодам.
3. Агент создаёт турнир с сегментами, подписывает их и даёт ссылку.

**Дальше одинаково.**

1. На странице турнира 8 сегментов, у каждого свой прогресс. Владелец сравнивает треки
   внутри сегмента, в любом порядке.
2. В результатах сегмента владелец ставит размер топа и при желании переставляет места.
3. «Создать видео» отдаёт агенту готовые сегменты. Агент монтирует ролик:
   интро → «Эпизод 1» с топ-5 → … → аутро. Главы плеера — названия эпизодов.

## Развилки

### P01. Что такое сегмент турнира

- Варианты: (а) турнир — набор сегментов, у обычного турнира один сегмент; (б) сегменты —
  отдельные турниры, связанные в группу.
- Рекомендация: (а). Пока сегмент один, интерфейс выглядит как сейчас. Старые турниры
  становятся турнирами из одного сегмента.
- **Решение:** как в рекомендации (владелец, 2026-11-05).

### P02. Как появляются сегменты

- Варианты входов:
  - несколько архивов в форме: архив = сегмент, имя файла = название;
  - один архив с папками: форма предлагает «разбить по папкам»;
  - один архив, разбивка потом в редакторе на странице турнира;
  - агент через MCP;
  - дозагрузка: архив добавляется в готовый турнир новым сегментом.
- Рекомендация: первые четыре сразу, все ведут к одному результату. Дозагрузка — кандидат А3.
- **Решение:** как в рекомендации (владелец, 2026-11-05).

### P03. Редактор разбивки

- Что внутри: сегменты списками, у трека ▶, название, исполнитель, альбом и папка.
  Можно создать, переименовать, переставить и удалить сегмент. Треки перетаскиваются или
  переносятся мультивыбором. Подсказка «по альбому», если теги есть.
- Правило: каждый трек всегда лежит ровно в одном сегменте. Новый турнир начинается
  с одного сегмента «Все треки».
- **Решение:** как в рекомендации (владелец, 2026-11-05).

### P04. Где идут сравнения

- Варианты: (а) только внутри сегмента, у каждого свой мини-турнир; (б) общий турнир,
  а сегменты только режут готовый рейтинг.
- Рекомендация: (а). В общем швейцарском турнире два трека одного эпизода могут ни разу
  не встретиться, и топ-5 эпизода выйдет случайным. Сравнений при этом меньше:
  80 треков одним турниром — около 280 пар, 8 сегментов по 10 — около 160.
- **Решение:** как в рекомендации (владелец, 2026-11-05).

### P05. Общие и свои настройки

- Рекомендация:
  - Схема, размер группы и слепой режим общие на весь турнир.
  - Размер топа, ручной порядок и данные для ролика у каждого сегмента свои:
    название, подзаголовок, постер.
  - Сегмент из одного трека готов сразу.
- **Решение:** как в рекомендации (владелец, 2026-11-05).

### P06. Перестройка после начала сравнений

- Варианты: (а) запретить; (б) разрешить, ответы перенесённого трека в старом сегменте снимаются
  после подтверждения «будет снято N ответов»; (в) разрешить и хранить старые ответы.
- Рекомендация: (б). Агент мог ошибиться с эпизодом, и это должно чиниться без пересоздания турнира.
  Готовый сегмент после правки снова становится незавершённым.
- **Решение:** как в рекомендации (владелец, 2026-11-05).

### P07. Когда можно делать видео

- Варианты: (а) когда готовы все сегменты; (б) по готовым сегментам, остальные доезжают по готовности.
- Рекомендация: (б). Монтаж можно начать по первым эпизодам. Новый готовый сегмент приходит
  в проект так же, как сейчас приходит новый рейтинг, с общим оформлением.
- **Решение:** как в рекомендации (владелец, 2026-11-05).

### P08. Что может агент в турнире

- Рекомендация:
  - Агент создаёт турнир из файлов с диска или из пула, раскладывает и переносит треки,
    подписывает сегменты и ставит им постеры.
  - Агент **не** отвечает на сравнения и не ставит места: их определяет человек.
  - Перенос, который снимает ответы, требует от агента явного подтверждения.
- **Решение:** как в рекомендации (владелец, 2026-11-05).

### P09. Слово

- Варианты: «сегмент» везде; «сет» в турнире и «сегмент» в ролике.
- Рекомендация: «сегмент» везде. Одно слово для человека, агента и кода, и в брифе оно уже есть.
- **Решение:** как в рекомендации (владелец, 2026-11-05).

## Кандидаты в объём

Список, из которого выбирался объём. Ядро — P01–P09 и основа SDK В1–В3. Что вошло,
сказано в разделе [«Объём»](#объём). Размер — грубая оценка работы.

### Блок А. Турнир с сегментами: дополнительно

| № | Идея | Зачем | Размер |
|---|------|-------|--------|
| А1 | Финал «лучшие из лучших» | Победители сегментов (top-1 или top-K) сравниваются между собой и дают сегмент «Финал» | средне |
| А2 | Блоки по местам | Один общий рейтинг режется на главы «50–41», «40–31»…, нумерация сквозная | мало |
| А3 | Дозагрузка сегмента | Новый архив в готовый турнир: вышел новый эпизод или сезон | средне |
| А4 | Свой порядок без сравнений | Маленький сегмент из 3–4 треков владелец расставляет сам | средне |

### Блок Б. Топ удобнее (человек)

| № | Идея | Зачем | Размер |
|---|------|-------|--------|
| Б1 | Перетаскивание мест мышью | Вместо ↑↓ по одной позиции | мало |
| Б2 | Прослушивание в результатах | Кнопка ▶ у позиции: проверить порядок перед роликом | мало |
| Б3 | «Лучший момент» трека | Отметка на экране сравнения или в результатах становится началом фрагмента в ролике | средне |
| Б4 | Правка названия и исполнителя | Кривые теги чинятся на сайте, а не в архиве | мало |

### Блок В. Возможности SDK для агента

Здесь только то, что расширяет возможное для агента. Готовых эффектов нет: раскрытие места,
итоговую таблицу, лесенку и заставку агент собирает из этих частей сам.

**Основа** — без неё сегменты до ролика не дойдут.

| № | Идея | Что даёт агенту | Размер |
|---|------|-----------------|--------|
| В1 | Сегменты в документе | Новая версия схемы. Источник отдаёт сегменты с названиями и местами внутри. Цель патча `segment`. Сегменты можно добавить, скопировать, переставить и удалить. Пресет красит все сегменты, сегмент переопределяет своё оформление и музыку. Старые проекты — один сегмент, выглядят как раньше | много |
| В2 | Сегменты разных видов | Топ, пикер и свободные (интро, аутро) в одном ролике | средне |
| В3 | Главы и таймлайн по сегментам | Главы `/watch` с названиями сегментов. Таймлайн отдаёт границы сегментов, и агент сам пишет таймкоды для YouTube | мало |

**Новые возможности**

| № | Идея | Что даёт агенту | Размер |
|---|------|-----------------|--------|
| В4 | Привязки к сегменту | Название, подзаголовок, номер, число мест и постер сегмента в любом узле: заставки любого вида | мало |
| В5 | Новые данные участника | Комментарий, альбом, очки турнира, обложка, отметка упоминания в привязках. «Лучший момент» сам становится началом фрагмента. Пары к Б3–Б7 | мало |
| В6 | Медиа текущего участника в любом узле | Картинка, видео и звук участника в обычных узлах: свои раскладки, фон из обложки, сцены со звуком | мало–средне |
| В7 | Набор участников в одной сцене | Контейнер раскладывает выборку участников, которая сама следует за рейтингом: все места сегмента или ролика, уже раскрытые, упоминания. Отсюда итоговая таблица, лесенка, тизер, блок упоминаний | средне |
| В8 | Размытие | Новый эффект для картинки, видео и карточки: размытый фон | мало–средне |
| В9 | Рендер части ролика | Сегмент или диапазон рендерится отдельным файлом в своём формате: серия шортсов из одного документа | много |
| В10 | Кадр вне таймлайна | Сцена, которая рендерится только картинкой: обложка ролика для YouTube | средне |
| В11 | Рецепты в `video_examples` | Готовые примеры: раскрытие места, заставка сегмента, итоговая таблица, лесенка | мало |

Связи: В5 показывает данные из Б3–Б7, В4 — данные сегмента из P05. Если пункт-источник
не берём, его пара в В уже не нужна.

## Объём

Владелец принял рекомендацию агента целиком.

**Входит**

- Турнир с сегментами по развилкам P01–P09: несколько архивов, архив с папками, редактор
  разбивки, сравнения внутри сегмента, свои размер топа и данные у сегмента, перенос трека
  с подтверждением, видео по готовым сегментам.
- Вход агента через MCP по P08: создать турнир из файлов с диска или из пула, разложить
  и перенести треки, подписать сегменты, поставить постеры.
- Удобство человека: Б1, Б2, Б3, Б4, Б5, Б6.
- SDK: основа В1–В3 и возможности В4–В8, В11.
  - В5 несёт комментарий (Б6), альбом из тегов, очки турнира, обложку (Б5) и «лучший момент» (Б3).
    Отметки упоминания в нём нет: Б7 не вошёл.
  - Выборки В7: все места сегмента, все места ролика, уже раскрытые места.

**Решение агента.** А3 рекомендовался с условием «если ролики будут по выходящим сериям».
Примеры владельца — Umineko и OST Key — законченные серии, поэтому А3 в объём не вошёл.
Владелец может вернуть его следующим задачам.

**Порядок работ** (рекомендация для плана): турнир с сегментами → вход агента → мост в SDK →
возможности SDK. Каждый этап проверяется вживую.

## Не входит

- Агент не отвечает на сравнения и не ставит места (P08).
- Готовые визуальные эффекты в SDK. Раскрытие места, заставку сегмента, итоговую таблицу,
  лесенку и тизер агент собирает из В4–В8, примеры дают рецепты В11.
- Отложенные кандидаты, каждый — отдельная задача при желании:
  - А1 — финал «лучшие из лучших»;
  - А2 — блоки по местам;
  - А3 — дозагрузка сегмента;
  - А4 — свой порядок без сравнений;
  - Б7 — почётные упоминания;
  - Б8 — исключить трек;
  - В9 — рендер части ролика (шортсы);
  - В10 — кадр вне таймлайна (обложка ролика).
