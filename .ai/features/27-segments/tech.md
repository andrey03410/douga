# Технические решения

## Исходная система

Проверены `prisma/schema.prisma`, `src/server/tournaments.ts`, `src/lib/upload.ts`,
HTTP турниров, `CreateTournamentForm.tsx`, обзор, сравнения и `ResultsPanel.tsx`.
Сейчас треки, батчи, ответы и рейтинг привязаны к турниру; движки чистые и получают список ID.
`finalize` сохраняет рейтинг, повторный вызов меняет только top-N.

Проверены `src/video/types.ts`, `compiler.ts`, `context.ts`, `src/server/studio/sources.ts`,
`timeline.ts`, `queries.ts` и создание проекта. Документ v1 хранит один источник и сцены;
компилятор повторяет их по всем участникам. Источник перечитывает рейтинг и удерживает
оформление по ID трека. План — JSON, общий для Remotion и HTML-плеера.
Карточки зон прочитаны: tournament, media, studio-sdk, render, mcp, dev-env.

## Решения

### T01. Хранение и совместимость турниров

- Варианты: отдельные турниры; сегменты внутри турнира.
- Рекомендация: `TournamentSegment` внутри турнира, nullable `segmentId` у Track,
  ComparisonBatch и Ranking. Старые данные лениво получают один сегмент «Все треки»
  без пересчёта рейтинга и ответов. Общие scheme/groupSize/blindMode остаются у турнира.
- **Решение агента (автономно):** рекомендация. У сегмента свои status/topSize/bonusOpponents,
  title/subtitle/posterArtId/order. Рейтинг остаётся уникальным по tournamentId+trackId.

### T02. Один движок, ограниченный сегментом

- Варианты: переписать движки; передавать им срез данных.
- Рекомендация: `getTournament(userId, id, segmentId?)` возвращает совместимый загруженный
  объект, с сегментом в `activeSegmentId` и отфильтрованными tracks/comparisons/batches/rankings.
  В `segments` остаётся полный список с прогрессом. Без segmentId выбирается первый сегмент.
  Все действия compare/undo/extend/finalize/reorder принимают segmentId; старые вызовы работают.
- **Решение агента:** рекомендация. Один трек готов сразу. Итоговый статус турнира агрегирует
  состояния сегментов. Только HTTP сравнения/результатов может менять ответы и места.

### T03. Редактор разбивки и снятие ответов

- Варианты: запрет после старта; полная очистка; точечное снятие.
- Рекомендация: атомарно применять полный состав `segments: {id?,title,subtitle?,posterArtId?,trackIds[]}[]`.
  Каждому треку ровно одно место; пустой сегмент допустим как черновик. Перенос снимает ответы
  с участием перенесённых треков и целые связанные батчи (экран — единица ответа), очищает
  рейтинги изменённых сегментов. Сервис сначала возвращает число снимаемых ответов,
  применение требует `confirmReset: true`. Повторная проверка внутри транзакции.
- **Решение агента:** рекомендация. Неперенесённые треки и ответы других сегментов сохраняются.

### T04. Импорт и данные трека

- Варианты: парсить ZIP в браузере; разбирать на сервере.
- Рекомендация: сервер читает несколько `file`, один архив можно разделить по папкам.
  Поля `segmentTitles` задают имена архивов; `splitFolders` делит по папке без общего корня.
  При одном плоском архиве — «Все треки», дальше редактор. Теги сохраняют album, embedded cover,
  исходную папку. Track получает comment/bestMomentSec/coverPath/coverArtId.
- **Решение агента:** рекомендация. Общая сумма архивов ограничена квотой роли;
  локальные файлы копируются, пул не перемещается. Ссылки на постеры/обложки проверяются по владельцу.

### T05. MCP турнира

- Варианты: HTTP от агента; инструменты поверх сервисов.
- Рекомендация: `tournament_list`, `tournament_get`, `tournament_create`, `tournament_segments_update`.
  Создание принимает массив сегментов с файлами из разрешённых MCP_LOCAL_MEDIA_DIRS либо assetId пула.
  Обновление разрешает структуру/подписи/постеры, но не rank, topSize и ответы.
- **Решение агента:** рекомендация. Каждый вызов заново проверяет роль и владение;
  снятие ответов требует явного confirmReset. Списки файлов расширяются тегами.

### T06. Документ v2 и компилятор

- Варианты: автоматически менять v1; сохранить v1 и добавить v2.
- Рекомендация: v1 сохраняется без изменения кадров. V2 добавляет `segments[]` с id, kind
  (`top|picker|custom`), title/subtitle/poster, sourceSegmentId, participantIds/roundIds,
  scenes, settings и audio. Источник отдаёт `source.segments[]` с метаданными и participantIds.
  Участники остаются в общей source.participants с уникальными ID, rank локален сегменту.
- **Решение агента:** рекомендация. Каждый сегмент компилируется тем же ядром в общий план,
  план получает интервалы segments, сцены — segmentId/title. Общие settings и пресет наследуются,
  сегмент их переопределяет. Патч segment и обычный set массива позволяют копировать/менять порядок.
  Компилятор ограничивает суммарную развёртку, не только каждый сегмент отдельно.

### T07. Новые примитивы SDK

- Варианты: отдельные готовые эффекты; расширение узлов.
- Рекомендация: привязки segment.title/subtitle/number/count, participant.comment/album/score;
  динамические медиа `$participant.visual`, `$participant.audio`, `$segment.poster`;
  контейнер с выборкой segment/document/revealed и дочерним шаблоном; ограниченный `style.blur`.
- **Решение агента:** рекомендация. Обложка входит в media.visual, лучший момент — в participant.bestMomentSec;
  он приоритетнее автоматического выбора фрагмента. V11 добавляет четыре проверяемых рецепта.

### T08. Синхронизация и главы

- Варианты: ждать весь турнир; включать готовые сегменты.
- Рекомендация: в новый проект турнира v2 входят только завершённые непустые сегменты.
  Reconcile обновляет данные, добавляет новые готовые сегменты с общими сценами,
  удерживает пользовательские сцены и оформление по sourceSegmentId/participantId.
  Главы берутся из интервалов плана в watch и офлайн; таймлайн возвращает эти границы.
- **Решение агента:** рекомендация. Временно снова незавершённый сегмент исчезает из источника,
  кастомные интро/аутро остаются. Старые v1-проекты используют прежний путь, пока явно не переведены.

## Затронутые зоны

- tournament — сегменты, импорт, сравнения, результаты, редактор.
- media — теги, обложки и защита используемых картинок пула.
- studio-sdk — v2, примитивы, источник, рецепты, синхронизация.
- render — blur, метаданные сегментов и проверка кадров/звука.
- mcp — инструменты турнира, новые примеры и контракт.
- dev-env — применение аддитивной схемы и проверочный прогон.

## Проверка

TDD для независимых сравнений, миграции старого турнира, переноса с подтверждением,
дубликатов/чужих ID, v2/патчей/наборов/бюджетов и сохранения v1. Итоговый QG:
`npm test` → `npm run build` → `npx tsc --noEmit`. Живой сайт: три входа импорта,
редактор, сравнения двух сегментов в разном порядке, прослушивание, данные и места,
MCP: подготовка турнира и монтаж смешанного документа. Реальные PNG/MP4 и звук,
главы watch/офлайн, снимки старого v1 до/после. Данные только отдельного проверочного аккаунта.
