# Технические решения

## Исходная система

- `CLAUDE.md` весил 19 КБ, и большую часть занимал абзац-changelog фаз. Карты кода не было.
  `README.md` весит 62 КБ. [`phases/README.md`](../../phases/README.md) и
  [`00-vision.md`](../../specs/00-vision.md) устарели.
- Был один скилл, [`verify`](../../../.claude/skills/verify/SKILL.md), и только в `.claude/`.
  `AGENTS.md` не было.
- Старое имя использовалось в `package.json`, `.mcp.json`, `src/mcp/server.ts`, в User-Agent
  у Shikimori и URL-импорта, в `layout.tsx`, `page.tsx`, `Setup.tsx`, `.env.example` и в доках.
- Репозиторий на GitHub публичный, в нём разрешены все способы слияния.
- Образец — корп-репы `~/www/apex` и `~/www/bitrix/modules`. Из них взяты `AGENTS.md` как
  единый вход, «индекс первым», общий каталог скиллов через симлинк и стадии с гейтами.
  Не взяты линтеры знаний, бюджеты в байтах, движок решений, трекеры хвостов и ратификация.

## Решения

### T01. Имя и объём переименования

- **Решение:** Douga. Меняются бренд на сайте (логотип, фавикон, тексты приветствия),
  `package.json`, ключ MCP-сервера (`douga`, инструменты станут `mcp__douga__*`),
  User-Agent, доки, а в архивных доках — упоминания имени. Репозиторий на GitHub
  переименовывается в `douga`. Доменные имена в коде (`Tournament` и т.д.) остаются:
  турнир — по-прежнему фича внутри продукта.

### T02. Папка на диске

- Варианты: переименовать сейчас или после вливания.
- **Решение:** после вливания. От пути зависят рабочая папка текущей сессии и
  память Claude (`~/.claude/projects/<путь>`). `.mcp.json` больше не держит абсолютный
  `cwd`: Claude Code запускает проектный сервер из корня проекта.

### T03. Вход для агентов

- **Решение:** основной файл — `AGENTS.md` (его читают Codex и Cursor).
  `CLAUDE.md` импортирует его через `@AGENTS.md`. Простыня статуса уходит в
  [`history.md`](../../history.md), грабли — в карточки.

### T04. Слой знаний

- **Решение:** в [`.ai/map/`](../../map/) по карточке на зону: dev-env, roles, tournament,
  media, shikimori, mcp, classic-video, render, studio-sdk. Каждая не длиннее ~80 строк и
  устроена одинаково: код, данные, как устроено, грабли, как проверить, история.
  Спеки и планы фаз 1–21 остаются архивом, контракты SDK 22–25 пока актуальны.
  Факты из личной памяти Claude (порт 3000, MCP через stdio-драйвер) переезжают в
  карточки, чтобы их видели все агенты.

### T05. Стадии и git

- **Решение:** `brief → product → tech → plan → build → review → merged`. Трек `tech`
  пропускает product, мелочь обходится без папки задачи. Состояние лежит во frontmatter
  `README.md` задачи. Нумерация продолжает фазы (с 22). Ветка `<тип>/NN-slug`,
  каждая стадия — коммит. Гейта после плана нет. Вливание через PR
  (`gh pr merge --merge`), и только после «принято» от владельца. Ворктри по
  умолчанию не используются: в них нет `.env`, `storage/` и `dev.db`, а dev-сервер
  конфликтует за порт 3000.

### T06. Скиллы и совместимость

- **Решение:** скиллы лежат в `.claude/skills/`. Для Codex есть симлинк `.agents/skills → ../.claude/skills`:
  Codex ищет навыки репозитория в `.agents/skills`. Cursor читает и `.agents/skills`, и `.claude/skills`.
  Набор: `feature` (новый, ведёт стадии) и `verify` (обновлён: QG-тройка и маршрут
  живых проверок по зонам). `video` (производство роликов через MCP) отложен до
  следующего ролика. `disable-model-invocation` не ставим: в Cursor этот флаг прячет скилл от модели.
- superpowers используется по желанию: его артефакты кладутся в папку задачи, а не в `docs/superpowers/`.
