# verify — QG и проверка вживую

## Порядок

1. **Зоны.** Собери изменённые файлы вместе с незакоммиченными:
   `git diff --name-only main` и `git ls-files --others --exclude-standard`.
   Сопоставь их с карточками [`.ai/map/`](../../../.ai/map/). Что проверять вживую,
   написано в разделе «Как проверить» каждой карточки.
   Если изменены только доки (`*.md`, `.ai/`), тройка не нужна: достаточно проверить
   ссылки и пути, затем перейти к шагу 4.
2. **Тройка** после последних правок, строго в этом порядке:
   - `npm test`. Запиши число тестов и файлов. Тесты занимают `prisma/dev.db`
     (около 10 минут).
   - `npm run build`. Сборка пишет в тот же `.next`, что и dev-сервер, и после неё
     у работающего dev-сервера разваливаются стили. Поэтому сначала выполни
     `lsof -nP -iTCP:3000 -sTCP:LISTEN`. Если там сервер владельца, спроси, можно ли
     собирать и потом перезапустить его. Если сервер твой, останови его до сборки.
   - `npx tsc --noEmit` — после build, иначе tsc споткнётся о пересоздаваемые `.next/types` (TS6053).
3. **Живые проверки** по зонам:

   | Что затронуто | Как проверить |
   |---|---|
   | Страницы и UI | dev-сервер (порт 3000 проверить заранее), драйв `puppeteer-core` и скриншоты, см. «Драйв UI» ниже |
   | API | HTTP-пробы с куки-логином, см. «HTTP-пробы без браузера» |
   | MCP | stdio-драйвер или `scripts/verify-studio.mjs`, см. [mcp.md](../../../.ai/map/mcp.md) |
   | Рендер | реальный MP4: кадры через `ffmpeg -ss`, звук через `volumedetect` |
   | Студия SDK | `npm run studio:worker -- --once --job JOB_ID` и `verify-studio`, см. [studio-sdk.md](../../../.ai/map/studio-sdk.md) |
   | Только доки и конфиги | достаточно проверить, что ссылки и пути живые |

4. **Запись.** В `verify.md` задачи укажи команды и цифры, что смотрел глазами
   и пути к доказательствам. Доказательства клади в `storage/…`: в git они не попадают.
5. **Честно.** Красный результат показывай с выводом. Parity по типам и юнитам не
   объявляй. Пропущенную проверку называй пропущенной и объясняй почему.

Ниже — рецепты и грабли прошлых фаз. Ищи нужную зону по заголовку.

## Запуск

```bash
npm run dev   # http://localhost:3000 (в фоне; лог в файл)
```

После изменений `prisma/schema.prisma`: `npx prisma db push && npx prisma generate`
и **обязательно перезапустить dev-сервер** — работающий процесс держит старый
Prisma-клиент в памяти и падает 500 «Unknown argument <новое поле>».
`npm run dev` сам делает `prisma generate` перед стартом, а если клиент всё же
устарел, ответ 500 приходит с человеческим текстом (`serverError` +
`staleClientHint`) и виден прямо в UI; `src/lib/prisma-client.test.ts` ловит
забытый `prisma generate` в `npm test`.

## Библиотека медиа (фаза 17)

Драйверы прогонов лежали в scratchpad сессии 2026-07-31: `from-url-e2e.mjs`
(HTTP: гость 401, мусорный URL, loopback и `169.254.169.254` отбиты живым
сервером, HTML-страница → `code: NOT_IMAGE`, реальная картинка в пуле),
`ui-sources.mjs` (табы источников, авто-детект вида ссылки, фолбэк
«Скачать как видео/аудио»), `ui-paste.mjs` (вставка синтетическим
`ClipboardEvent`: файл, `<img src>`, текстовая ссылка, игнор видео-ссылки и
вставки в поле), `ui-rename.mjs` (Enter/Esc/ошибка), `bulk-delete.mjs`
(`Shift`-диапазон + подтверждение с последствиями + каскад карточки),
`ui-usage.mjs` (честный счётчик), `ui-account.mjs` (сводки и ленивые списки),
`measure-account.ts` (замер старого и нового кабинета на реальном аккаунте).

Гочи:
- Импорт по ссылке в тестах требует `MEDIA_URL_ALLOW_PRIVATE=1` — иначе
  фикстур-сервер на `127.0.0.1` отбивается политикой адресов (это и проверяется
  отдельным кейсом).
- Ветку `NOT_IMAGE` в UI дешевле застабить `page.setRequestInterception`, чем
  искать публичный адрес, который отдаёт HTML на путь с `.png`; отцепляй
  обработчик (`page.off`) **до** выключения интерсепции, иначе `req.continue()`
  падает.
- В карточке пула теперь два `input`: чекбокс выбора и поле имени. Селектор
  `.art-card input` берёт чекбокс — для имени нужен `.rename-input`.
- Ref внутри `setState`-апдейтера читать нельзя: апдейтер выполняется на
  рендере, когда «якорь» `Shift`-диапазона уже перезаписан. Диапазон считается
  до вызова `setState` (см. `useMediaPool.toggleSelected`).
- После правки `prisma/schema.prisma` (в фазе — `RenderJob.outputBytes`)
  dev-сервер обязательно перезапускать, иначе роуты кабинета отвечают пустым
  телом на старом клиенте.

## Множественные сравнения (фаза 18)

Драйверы лежали в scratchpad сессии 2026-08-01: `g-setup.mts` (создаёт турнир с
треками прямо в БД — ZIP для этого не нужен, аудио в драйве не играется),
`g-http.mjs` (HTTP: группа вместо пары, приём ранжирования, отказ устаревшему
экрану, «остальные примерно равны», отмена экрана целиком, смена размера на ходу
с клампом, доигровка плана, «Ещё раунд» и рост определённости, закрытый
завершённый турнир), `g-ui.mjs` (экран: клики по порядку и цифровые клавиши,
бейджи мест, «Сбросить», ранний стоп, селектор размера, возврат к парной
раскладке при 2, панель «План пройден»), `g-legacy.mts` (read-only регрессия по
реальным турнирам), `scale.ts` / `quality.ts` (симуляция на 201 треке: экраны,
прослушивания, Спирмен, определённость), `greedy.mjs` / `greedy2.mjs` (сравнение
эвристик набора группы в круговой).

Гочи:
- Замеры **обязательны при равном бюджете прослушиваний**, а не «до конца
  плана»: план при большом k заканчивается в 4 раза раньше, и если этого не
  учесть, группы выглядят хуже пар (10 % определённости против 36 %), хотя при
  равном времени они дают 99 %.
- Круговая с группами не дотягивает до теоретического дна: экран берут только
  треки, которые все друг с другом ещё не встречались. Умные эвристики (по
  максимуму/минимуму открытых пар, по связности кандидатов) проверены — каждая
  выигрывает на одних размерах поля и сильно проигрывает на других, поэтому
  стоит простая жадность по порядку загрузки. Гарантия, которая держится всегда:
  любая группа больше пары стоит не больше половины экранов от парного режима.
- Оценка экранов должна учитывать текущий экран: рост размера группы уменьшает
  план, и прогон, переключённый с пар на пятёрки, уже за новой оценкой — иначе
  на экране появляется «Экран 3 из ~2».
- Порядок `createdAt` в SQLite — миллисекунды. Два экрана, отвеченных внутри
  одной миллисекунды, возвращаются в произвольном порядке, а от него зависят и
  «первый ответ побеждает» в `lookup`, и то, какой экран снимет отмена. Добивай
  сортировку по `id`.
- `finalize` завершённого турнира больше не проверяет движок: фаза 18 сменила
  правило завершения швейцарки (соперники на трек вместо раундов), и старый
  прогон с байями оказывается на одно сравнение коротким — без этой поправки
  ломается обычная смена top-N на готовом топе.
- `server-only` не резолвится вне Next, поэтому read-only проверки на реальной
  БД собирай из доменных модулей, а не импортом `src/server/*`.
- Драйвер, который щёлкает «первую неотмеченную карточку», отвечает
  бессвязно — и это полезный кейс: индикатор обязан показать противоречия
  (в прогоне вышло «расставлено 0 % пар · противоречий 36»), а не выдать
  уверенный топ.

## Драйв UI (headless Chrome)

Playwright/puppeteer в deps нет; есть `puppeteer-core` (devDep) + системный Chrome
`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`:

```js
import puppeteer from "puppeteer-core";
const browser = await puppeteer.launch({
  executablePath: "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome",
  headless: "new",
  args: ["--no-sandbox"],
});
```

- Логин: заполнить `input[name=email|password]` на `/login`, submit, ждать навигацию.
- Скрипт-драйвер должен резолвить `puppeteer-core`: либо класть его рядом с
  `node_modules` проекта, либо `ln -s <project>/node_modules <scratchpad>/node_modules`.
- Модалка артов: `.modal`, карточки `.art-card`, скрытый файл-инпут
  `.modal input[type=file]` → `input.uploadFile(...пути)` (мультизагрузка).
- Кроп: `.cropper-box` (react-easy-crop), зум — `input[type=range]` через нативный
  сеттер + событие `input`; сдвиг — mouse down/move/up по центру бокса.
- `confirm()` удаления: `page.once("dialog", d => d.accept())` **до** клика.
- После «Применить» конфиг перезагружается с ffmpeg-анализом сниппетов — ждать
  селектор (до 20 с), не фикс-таймаут.

Готовый драйвер полного сценария (менеджер → поиск → кроп → сброс → «Недавние»)
лежал в scratchpad сессии 2026-07-10: `ui-verify.mjs` — можно взять за образец.

## Видео-фикстуры и готовые драйверы (фаза 4)

Смешанный архив (mp3 + mp4 со звуком/без) и клип для пула генерируются ffmpeg-ом
(`testsrc`/`smptebars`/`sine`) — образец `make-mixed-zip.mjs` в scratchpad сессии
2026-07-10; там же `video-e2e.mjs` (полный HTTP-флоу: смешанный турнир → kinds →
пул-видео с постером → подмена звука/сдвиг/кроп → негативные пробы) и
`video-ui-verify.mjs` (слепой режим прячет видеоряд, менеджер с бейджами,
кроп по `<video>`, переключатель звука).

Гочи:
- 413-лимит нельзя пробить через undici (не даёт подделать Content-Length) —
  бери curl с сессионной кукой (`get-cookie.mjs` печатает Cookie-заголовок).
- Видео в кроп-редакторе декодирует первый кадр ~1 c — скриншот сразу после
  `waitForSelector` будет чёрным; жди `readyState === 4` или 1–2 c.
- Headless-рендер с видео работает: `REMOTION_BROWSER_EXECUTABLE="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`
  из `.env`; проверяй результат извлечением кадров из выходного MP4
  (`ffmpeg -ss <t> -i out.mp4 -frames:v 1`).

## Роли и лимиты (фаза 5)

Готовые драйверы в scratchpad сессии 2026-07-10: `roles-e2e.mjs` (гость 401/
редиректы, квоты юзера 1 архив/100 МБ/пул 100 МБ, рендер 403, админка со сменой
ролей без перелогина, удаление юзера) и `roles-ui-verify.mjs` (welcome,
регистрация через UI, скрытая кнопка рендера, кабинет, админка).

Гочи:
- `page.click('button[type="submit"]')` попадает в кнопку «Выйти» топбара —
  она первая submit-кнопка в DOM. Кликай кнопки форм по тексту.
- Фикстура «слишком большого» архива не должна быть ZIP-ом из нулей: deflate
  сожмёт 101 МБ до ~100 КБ и лимит честно пропустит файл. Шли несжатое тело —
  413 срабатывает по Content-Length до разбора архива.
- `e2e-setup.mjs` сидирует e2e@test.local уже с ролью admin (рендер и админка
  доступны); для сценариев с лимитами создавай отдельного юзера роли user.
- Роль читается из БД на каждый запрос: смену роли можно проверять живой
  сессией без перелогина.

## Видео-проекты: пикер и ручной топ (фаза 6)

Готовые драйверы в scratchpad сессии 2026-07-11: `projects-e2e.mjs` (аудио в
пуле, жизненный цикл пикера + проверки превью-плана вплоть до геометрии 3+2,

Гочи:

- Кадр ровно на стыке фаз топа (интро→сегмент) — чёрный из-за фейдов; бери
  середину фазы.
- Джобы проектов и турниров живут в одной таблице: любые фильтры владения
  обязаны быть `OR: [{tournament:{userId}}, {project:{userId}}]` — забытый
  фильтр всплывает как 404 на done-джобе.

## Полировка (фаза 7): плейлист, фрагмент-превью, аудио-фейды

Драйверы в scratchpad сессии 2026-07-13: `polish-e2e.mjs` (плейлист: legacy-

  (фейды, лупы) должны опираться на реальный хвост потока, не на пробу.

## Импорт по ссылке (фаза 8, yt-dlp)

Драйверы в scratchpad сессии 2026-07-13: `yt-e2e.mjs` (конвейер на локальном
HTTP-источнике + реальный YouTube), `yt-ui-verify.mjs` (панель в менеджере

Гочи:
- В этой сети **googlevideo.com заблокирован**: метаданные YouTube (`-J`)
  работают, а сама загрузка падает по SSL-таймауту. Позитивный путь проверяй
  локальным HTTP-источником (generic-экстрактор качает прямые mp4/mp3);
  от реального YouTube жди только title + честную ошибку про CDN.
- Системный yt-dlp (apt) слишком стар и сломан YouTube-ом; свежий бинарник
  качается в `storage/bin/yt-dlp` автоматически (или задай YTDLP_PATH).
- Рестарт dev-сервера осиротляет running-джобы: `listDownloads` помечает
  протухшие (updatedAt старше 10 мин) как failed — это ожидаемо.

## Импорт из Shikimori (фаза 9)

Драйвер в scratchpad сессии 2026-07-14: `shikimori-ui-verify.mjs` (менеджер
медиа → блок Shikimori: поиск «naruto» в режиме «Аниме» → дропдаун с
постерами и фактами → клик «⬇ В пул» → карточка в пуле; переключение на
«Персонажи»).

Гочи:
- Базовый хост — `SHIKIMORI_BASE_URL` в `.env` (дефолт `https://shikimori.io`);
  домен периодически мигрирует (`.one → .io → …`) — смена одной переменной
  переносит интеграцию на новый хост без изменений в коде.
- Интеграционный тест (`src/integration/shikimori.integration.test.ts`) НЕ
  ходит в реальный Shikimori — поднимает локальный HTTP-источник и направляет
  `SHIKIMORI_BASE_URL` на него (паттерн из `downloads.integration.test.ts`).
  Реальный сетевой смоук — отдельно, вручную/скриптом в scratchpad.
- Превью в дропдауне (`<img class="shk-thumb">`) грузится **напрямую с
  Shikimori кросс-доменно**, не проксируется через наш бэкенд — если сеть
  режет хост, миниатюры не появятся, хотя JSON поиска (через наш API) может
  отработать. Сам импорт постера всегда идёт через бэкенд (`fetchPoster`).
- Панель — `.shikimori-panel`, переключатель типов — кнопки с текстом «Аниме»/
  «Персонажи» (не отдельный класс), результаты — `.shk-result`, кнопка
  импорта — «⬇ В пул», успех — инлайн-текст «в пуле» (замена кнопки).
- Переключая тип **и** тут же вводя текст в одном шаге — не скриншоть сразу
  после `waitForSelector('.shk-result')`: стейт результатов не чистится, пока
  новый фетч не резолвится, так что селектор мгновенно матчит **старые**
  результаты предыдущего типа. Сначала переключи тип, отдельно введи запрос,
  подожди дебаунс+сеть (или сверяй по отличимому полю — у аниме факты вида
  «год · тип · ★рейтинг», у персонажа — просто оригинальное имя).
- Полный `npm test` держит блокировку на `prisma/dev.db`; перед прогоном
  всего сьюта останавливай dev-сервер (общая SQLite-база даёт конфликты
  блокировки при параллельном доступе).

## Списки пользователя Shikimori в MCP (фаза 13)

Драйверы в scratchpad сессии 2026-07-30: `shiki-user-smoke.ts` (сервисный слой
против реального shikimori.io: профиль → список с фильтрами → избранное →
персонажи просмотренного → импорт постера) и `mcp-live.ts` (то же по
stdio-протоколу MCP через `@modelcontextprotocol/sdk` — образец живого прогона
инструментов без локального стенда).

Запуск: `npx tsx --env-file-if-exists=.env --tsconfig tsconfig.mcp.json <script>`;
скрипту в scratchpad нужен симлинк `node_modules` на проектный (иначе
`Cannot find module 'ffmpeg-static'`), а дочернему MCP-процессу — проброс
`DATABASE_URL` из `.env` (относительный `file:./prisma/dev.db` не резолвится) и
`MCP_ACTOR_EMAIL` существующего аккаунта.

Гочи:
- **Лимиты 5/сек И 90/мин**: серия вызовов (профиль + список + роли на каждое
  аниме) упирается именно в минутный — на ~90-м запросе. Клиент держит оба
  (250 мс + скользящее окно 80/мин, ретраи 2/8/20 с) — при добавлении новых
  эндпоинтов ходи через общий `getJson`, иначе лимит вернётся. Обход сотни
  аниме занимает больше минуты — это нормально, не «зависло».
- **Постер**: `/system/...` из REST — уменьшенная и иногда устаревшая копия;
  на сайте показан `/uploads/poster/...` из GraphQL `poster.originalUrl`
  (у аниме это 685×975 вместо 225×350). `importPoster` берёт свежий, откат на
  legacy — молчаливый, так что «картинка не как на сайте» = фолбэк сработал.
- Аниме без арта отдаёт `image.original = /assets/globals/missing_original.jpg`
  — мапперы превращают такой путь в `null`; не подставляй его в импорт.
- Записи `kind: music`/`pv`/`cm` в списке юзера есть, а персонажей у них нет
  (`/roles` отдаёт только `person`) — сценарий «персонажи из просмотренного»
  обязан фильтровать по `kind`.
- Избранное отдаёт только `x64`-миниатюру: `posterPath` строится
  `resizeImagePath(..., "original")`, запрос-суффикс (кэш-бастер) сохраняется.
